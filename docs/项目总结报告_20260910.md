## 三、运行框架与进程架构

**16 个常驻进程**由 `launcher.py` 统一管理（PID 落盘 `.weavemind/pids.json`，支持守护巡检、连续失败隔离 300 秒）：

| 类别 | 进程 |
|---|---|
| 编排 | orchestrator（订阅 `orchestrator:main`） |
| 接入 | webui（TCP 8080，默认绑定 127.0.0.1） |
| 能力 Worker（11） | web_search / web_fetch / content_summary / code_execution / file_io / package / data_loader / data_analyzer / model_trainer / report_generator / react_agent —— 纯 Redis 队列通信，不监听端口 |
| 辅助（3） | critic（计划评审）、guardian（心跳监护，15s 巡检 / 45s 判死）、metrics（指标采集） |
| 可选 | scheduler（每日进化，默认关）、vite（前端 dist 缺失时，5173） |

**Redis 是唯一中枢**，承担三个角色：

- **消息总线**：`orchestrator:main`（任务投递）/ `orchestrator:response|progress`（进度）/ `orchestrator:alert`（告警）/ `orchestrator:plan_review` / `agent.kill:{id}` 等 8 个频道
- **服务发现注册表**：`agent:{id}`（能力/状态/心跳）、`capability:{cap}`（能力倒排索引）
- **任务台账**：`task_queue:` / `task_result:`（派发与回传）、`llm_usage_task:` / `llm_usage_month:`（成本）、`checkpoint:`（断点）、`plan_confirm:`（HITL）

**持久化**：SQLite `agents.db`（task_history / sessions / agents / checkpoints 四表）+ JSON 台账（share_links / evolution_history / templates.json / consolidation_stats.json）+ 任务工作区（report.md / financials.json / clean_chart_data.json / acceptance_report.json）。

## 四、运行逻辑（一次任务的完整链路）

1. **接入**：`POST /task` → 注入检测 / 限流 → 双端点余额预检（不足直接 503）→ 结果缓存命中检查 → 投递 `orchestrator:main`，登记 PENDING
2. **规划**：模板路由优先（命中确定性模板则跳过 LLM 规划）→ 否则 planner LLM 出计划 → 接线依赖 / 去环 / 注入 Skill 标准 → 可选 HITL 计划确认
3. **结构化预载**：`route_structured` 按 **A股排行 → 加密货币 → 宏观 → 新闻/行业 → 财务** 顺序尝试（命中则减少下游步骤，miss 等 2s 重试一次）
4. **执行**：DAG 并行调度（默认 max_parallel=3），逐步派发给对应 Worker；单步带重试、契约校验、超时控制（step ≤ task_timeout，code_execution ≥ 600s）
5. **回收**：BRPOP 结果 → 归一化 → 死链过滤（URL 存活探测）→ 结果回写供下游注入
6. **验收**：报告生成后运行确定性验收器（数字溯源三档 / 来源声明真实性 / 交付完整性 / 数据时效 / 免责声明），落盘 `acceptance_report.json`
7. **反思**：验收不达标 → 单步重做或追加步骤迭代（分级预算：排行 2 轮 / 财务 3 轮 / 通用 3 轮），含三级提前终止（报告未改善 / gaps 签名未变 / 核心已完成）
8. **交付**：终态判定（SUCCESS / FAILED / **SUCCESS_WITH_ISSUES**）→ 报告组装 + 图表章节内联 → 记忆沉淀（验收 pass 才沉淀策略）→ 模板固化 → SSE 推送前端

**贯穿全程的护栏**：stall 看门狗（60s 无进展判死）、guardian 心跳监护、每任务 LLM 调用预算熔断（max_calls / max_seconds / max_cost）、checkpoint 断点续跑、反思收敛判定。

## 五、功能清单

### 交付能力

- **11 个 Worker**：搜索（DDG 逐引擎探活 + Bing 双通道）、抓取（SSRF 防护 + IRI 编码）、内容总结（本地 LoRA 优先）、代码执行（生成-校验-修复 3 轮 + TDD）、文件读写（路径防穿越）、打包、数据加载 / 分析 / 模型训练、报告生成（过短重试 + 模板兜底）、ReAct 工具循环
- **6 类结构化数据源**（全部免费、无需 key）：A股与美股排行（东财/新浪/腾讯，规模感知全市场分页）、港股财务（东财）、美股财报（SEC XBRL）、加密货币（CoinGecko）、宏观指标（FRED）、新闻（Google News RSS → Bing → ddgs 三级降级）
- **数据处理管线**：搜索 → 清洗（实体频率 / 行情 / 份额 / 宏观 / 趋势等 8 类字段）→ 图表规格强校验 → 确定性渲染（色盲友好、饼图加和校验、柱状从 0）→ 视觉 QA 自动修复（最多 3 轮，残留降级为草稿图）→ 报告章节内联

### 可信交付（核心差异）

- **数字三档溯源**：`引用值`（可溯源到来源）/ `计算值`（算术可验证，容差 0.5%）/ `模型知识`（强制明示标注）
- **确定性验收器**：来源声明白名单匹配、死链检测、占位与完整性检查——不达标自动触发反思重做
- **溯源体检 API**：`POST /api/verify` 可把任意研报丢进来，返回"多少数字可验证、哪些是模型猜的"
- **合规护栏**：内置红线（禁止具体投资配比与收益率承诺）+ 强制免责声明 + 分享页匿名访问控制

### 智能进化

- **记忆**：ChromaDB 三集合（对话 / 成功策略 / 提示词改进），验收 fail 时禁止策略沉淀防污染；策略 TTL 90 天 + 容量治理
- **策略进化**：每日调度 → 3 变体变异（temperature / 过滤规则 / 提示词）→ LLM 裁判锦标赛 → 稳定性判定 → 人工审批 → 灰度分流（按 task_id 哈希分桶）→ 成功率 <50% 自动回滚
- **评测体系**：Ragas 式 4 指标 LLM judge（答案正确性 / 忠实度 / 上下文召回 / 上下文精确率）+ 失败任务自动生长评测集 + CI 确定性闸门 + 任务内 0.7 阈值反思闸门
- **本地模型链路**：glm-4-flash 蒸馏 → QLoRA 微调 → 多端口 LoRA 服务 → worker 层推理接入；cloud / hybrid 模式三级优先级切换，质量回退 >10pp 自动切回云端
- **提示词炼油 + 模板固化**：任务完成后后台提炼提示词改进（进 RAG）；同域同能力链连续通过则固化为确定性模板

### 产品化

- **Web 控制台 10 页面**：任务控制台 / 智能体 / 历史 / 健康 / 记忆与进化 / 评测 / Skill / 指标 / 审计 / 设置；React 18 + Vite 5 + zustand，SSE 为主 + 2s 轮询兜底，路由懒加载
- **多用户与安全**：PBKDF2 密码 + HttpOnly 会话 Cookie + 防爆破锁定、审计日志、角色门控（config/audit 仅 admin）、密钥脱敏下发
- **交付形态**：报告分享页（可选密码 + 有效期）、PDF 导出、通知三通道（Webhook / Server酱 / 邮件）、多项目工作区、定时任务、MCP 兼容
- **代码沙箱三模式**：docker（断网 + 只读根 + 内存/CPU 限制）/ restricted（剥密钥 + 工作区隔离）/ none；docker 不可用自动降级并标记 `sandbox_degraded`
- **成本可观测**：模型分级路由（planner / exec / judge 三档）、月度预算超限自动降级、每任务 token 台账、LLM 响应缓存

## 六、项目特点

1. **确定性优先**：数字、来源、图表、验收全部交给脚本判定，LLM 只负责语义与叙事——区别于"提示词祈祷式"Agent 的根本设计。
2. **全链可视化**：计划树实时生成、每步状态可见、报告带溯源徽章，不是黑盒聊天框。
3. **诚实降级哲学**：每条链路都有明确降级链（搜索→Bing→ddgs→诚实返回空；财务→多源兜底；沙箱→自动降级标记），宁可标 `SUCCESS_WITH_ISSUES` 也不伪造。
4. **自我改进闭环**：记忆 → 策略沉淀 → 模板固化 → 提示词炼油 → 评测集生长 → 策略进化，六条沉淀路径互相补充，且都有准入门槛与自动回滚。
5. **工程完整度高**：640 个测试用例、CI 五道闸门（密钥扫描 / 编译 / 测试 / 评测集 / 验证器）、时间轴规范文档、部署指南含无 Docker 方案。
6. **本地优先**：无 Docker 可用本机 Redis、本地可跑 QLoRA、数据与密钥不出本机、支持完全离线降级。
