# 新人运行包构建说明（Windows · 本地候选包）

目标形态：**下载并解压便携包 → 双击唯一入口 → 浏览器内完成必要引导 → 开始研究**。
本文件说明怎么构建、包里有什么、怎么核对；干净环境验收属 N4，构建报告会明确标注"未验"。

## 1. 构建

```bash
python scripts/build_run_package.py --version 2026.10.01 --out dist
```

常用参数：

| 参数 | 说明 |
|---|---|
| `--version` | 包版本（默认当天日期）。写进 `package_manifest.json` 与包内 `VERSION`，也是应用识别的"运行身份" |
| `--index-url` | wheel 索引（默认阿里云镜像，仅接受 https 公网地址） |
| `--python-sha256` / `--redis-sha256` | 固定运行时 / 便携 Redis 的 zip 摘要；未固定时把实际摘要写进报告 |
| `--offline-dir` | 离线素材目录（预放 `python-3.11.9-embed-amd64.zip` 与 `redis-windows.zip`） |
| `--font <path>` | 随包分发的中文 TrueType 字体（可选；Windows 默认用系统字体） |
| `--skip-fetch` | 只做打包与扫描，不下载（用于检查清单与扫描逻辑） |

构建产物：

- `dist/weavemind-<版本>-win-x64/`：可运行的包目录
- `dist/weavemind-<版本>-win-x64.zip`：分发压缩包（`--out` 下另附 `build_report.json`）

## 2. 包里有什么

| 部件 | 内容 | 说明 |
|---|---|---|
| `runtime/` | 可重定位 Python 3.11（python.org embeddable）+ `Lib/site-packages` | 不依赖系统 Python；`._pth` 必须同时含 `import site`、`Lib\site-packages` 与 **`..`（运行包根目录）**——带 `._pth` 的解释器是隔离模式，不加 `..` 时 `python launcher.py` 会 `ModuleNotFoundError: db_paths` |
| 应用源码 | 根级 `.py`、`workers/`、`adapters/`、`charts_pipeline/`、`structured_pipeline/`、`prompts/`、`skills/`、`validators/`、`models/` | 按**显式清单**拷贝；不含 `test_*`、`_trial_*`、`docs/evidence`、日志 |
| `frontend/dist/` | 已构建前端 | 新人不需要 Node |
| `demo/demo_brief.md` | 内置演示简报（合成数据） | 无密钥的新人在页面里唯一能看的内容；页面常驻标注"内置演示，非本次实时生成" |
| `.weavemind/downloads/redis-windows.zip` | 便携 Redis（可选随包） | 有它则首次启动**离线复用**，不再联网取 Redis |
| `运行说明.txt` | 新人最短说明（UTF-8 BOM，记事本可读） | 解压后第一眼看到"双击哪个文件、接下来干什么"；内容随构建事实变化（Redis/字体是否随包） |
| `start.bat` / `stop.bat` | 唯一入口与停止 | 入口只调 `python launcher.py up`（统一控制器）；**优先使用包内 `runtime\python.exe`**，系统 Python 只作回退 |
| `config.example.json` | 配置模板 | 首次运行由控制器进引导写 `config.json`；**包内不含任何真实密钥** |
| `package_manifest.json` | 版本 / 平台 / 组件 / 逐文件 SHA256 | 也是应用识别"包版本"的依据（`runtime_identity = package:<版本>`） |
| `requirements-runtime-win.lock` | Windows(cp311) 运行依赖锁 | 与 Linux 锁分开生成；见下 |

明确**不进包**：`config.json`、`agents.db`、`.env`、日志、任务工作区、`requirements.lock`
（整机快照）、任何密钥与历史数据。构建结束会做一次**秘密扫描**与**构建机绝对路径扫描**，
任一命中即构建失败（`ok: false`，退出码非 0）。

## 3. 平台锁（不要混用）

- `requirements-runtime.lock`：**manylinux2014_x86_64 / cp311**，供 CI 与 Docker；
- `requirements-runtime-win.lock`：**win_amd64 / cp311**，供本运行包。

生成：

```bash
python scripts/make_lock.py --runtime --platform win_amd64 --python-version 3.11 \
  --out requirements-runtime-win.lock --index-url https://mirrors.aliyun.com/pypi/simple/
```

`--out` 是必须的：早前固定写 `requirements-runtime.lock`，用 Windows 平台参数生成时会
把 Linux 锁覆盖掉（CI/镜像随后按 Windows 锁安装）。现在平台不同的锁写不同文件。

依赖安装两段式：先整体只取 wheel；对目标平台**没有 wheel** 的包（如 `jieba` 只有源码包），
在构建机上按宿主解释器构建后搬进包内 site-packages，并在报告里标注"按宿主构建（纯 Python
包假设）"，最后由包内解释器导入验证兜底。

## 4. 构建后自检（报告里逐项可见）

| 检查 | 判定 |
|---|---|
| 包内解释器 | `runtime/python.exe -c "import ssl, sqlite3, redis, aiosqlite, httpx"` **且导入项目模块**（`db_paths, cli_text, task_intent`）——只验第三方包会漏掉"包根不在 sys.path"这类致命问题 |
| 包根可见性 | 打印 `project_root_on_path`：确认某个 `sys.path` 条目下存在 `launcher.py` |
| 可选包导入 | `WM_PACKAGE_IMPORT_CHECK="jieba ..."` 时逐个试导入，结果如实记录（不拦构建） |
| 秘密扫描 | 命中 `sk-*`、密钥赋值、私钥块 → 构建失败 |
| 绝对路径扫描 | 包内出现构建机路径 → 构建失败 |
| 摘要 | Python 运行时 / 便携 Redis / 最终 zip 各给 SHA256 |

## 5. 端口与外部服务（包内行为）

- 8080 被别的程序占用：本实例**让位**到空闲端口，并把实际端口写入 `.weavimind/runtime_ports.json`；
  `launcher.py url`、webui 子进程与浏览器打开的是同一个端口。显式设置 `WEB_PORT`（或
  `config.json web.port`）时不自动改，只如实报告冲突。
- 6379 被别的程序占用、或上面是版本过低的 Redis（<6，如 Redis 5）：未显式配置时本实例另起
  便携 Redis 于空闲端口；**不停用、不接管**对方进程（`stop.bat` 也只停本项目启动的那个）。
- 企业代理（`HTTP_PROXY`）：回环健康检查显式不走代理，并把 `localhost,127.0.0.1,::1` 追加进
  `NO_PROXY`——否则会出现"服务在跑却报工作台未响应"。

## 6. 已知边界（如实记录）

- **干净环境未验**：构建报告里 `clean_env_verified=false`。真正的"无 Python/Node/Docker
  机器上解压双击"验收属 N4；当前最强证据是**净化环境的同一台机器 + 中文与空格路径**实跑
  （见 [新人上手指南](新人上手指南.md) 第 5 节的验证程度表）。
- 中文字体：Windows 默认用系统字体；Docker 路径仍缺字体（`WEAVEMIND_PDF_FONT` 可指定）。
  随包分发字体请显式 `--font`（注意字体许可）。
- 便携 Redis 只绑回环、按实例管理；遇到端口占用或 Redis 5 不会杀掉/接管他人服务。
- 包体积取决于运行闭包（含 chromadb / pandas / matplotlib 等）；不打包训练/CUDA/游戏依赖。
- 发版前只生成本地候选包与说明；**不**自动发布 Release、不上传任何数据。
