## A. 图表信任（P0，串行依赖：A1→A2→A3）

### A1. 散点去重误杀修复（BUG-9）
- **背景**：`RENDER_CHART_SCRIPT` 去重指纹 `(label,value,unit)` 过粗，散点图与柱状图 y 值相同即被判重，用户点名的量价散点连续两次被 SKIP
- **改动**：`chart_assembly.py`（RENDER_CHART_SCRIPT 常量）
- **要点**：指纹加入 `spec.type`；scatter 行取 `(x=caliber/年份或label, y=value)` 二元组而非单值；同 type 才比对
- **验收**：test_delivery_chain 补用例：bar+scatter 同数据共存，两者都渲染；现有 176 测试零回归
- **预估**：0.5 天

### A2. 多轮渲染坏图残留清理（BUG-10）
- **背景**：每轮渲染只覆盖自己产出的 chart_N，上一轮坏图（乱码标签）残留进入交付 zip
- **改动**：`chart_assembly.py`（RENDER_CHART_SCRIPT main）
- **要点**：渲染循环开始前删除目录内既有 `chart_N.png` 并重置 manifest 的 chart_N 条目（保留 financial_trends 等语义图条目）；manifest 与磁盘对账（有文件无条目/有条目无文件都修复）
- **验收**：连续两轮渲染，第二轮后目录中 chart_N 与 manifest 完全一致；乱码图不残留
- **预估**：0.5 天

### A3. 图表内联选择修复（BUG-11）
- **背景**：正文引用 `top10_volume`/`volume_price` 图名，实际嵌入 chart_2/3（乱码图），最好的 chart_1 未内联
- **改动**：`workers/report_generator_worker.py`（`_embed_charts_inline`）
- **要点**：匹配优先级改为 spec.title/conclusion 关键词 → 正文引用名；无匹配时选 manifest 中 keywords 命中最高分图；仍无则集中插到"数据来源"前并打日志
- **验收**：试运行同 goal 复跑，chart_1（TOP10 柱状图）出现在"成交额分布"小节后；引用名与实际图一致
- **预估**：1 天

### A4. 图表标签清洗与数值排序（BUG-12）
- **背景**：x 轴标签出现"N.股票名最新价"垃圾后缀与"12全市场规模画"乱码碎片；数字序号按字符串排序（12,13,19,3…）
- **改动**：`chart_assembly.py`（`short_label` 与渲染端）
- **要点**：标签清洗剥离前导"N."序号与指标后缀（最新价/涨跌幅）；序号提取为 int 排序；清洗后仍含 3+ 连续无语义字的标签 → SKIP 该行并计数进 spec.missing
- **验收**：任务5 的 chart_3 重渲染：标签为纯股票名、按数字序排列；乱码标签行被剔除且 missing 标注
- **预估**：1 天

### A5. 参考来源 URL 校验（BUG-13）
- **背景**：参考来源[1]输出 `[结构化数据块]`（非 URL）作为链接
- **改动**：`workers/report_generator_worker.py`（来源清单生成）
- **要点**：URL 非 `http(s)://` 开头 → 转为纯文字说明（"新浪行情中心（结构化数据，无公开链接）"）；结构化数据块的来源统一注入 fetched_at 时间戳
- **验收**：新报告参考来源区无无效链接文本；溯源页（C 组）不出现死链误报
- **预估**：0.5 天

### A6. 图表发布级/草稿级分级
- **背景**：乱码图进入交付损伤专业形象；"宁缺毋滥"需要机制化
- **改动**：`chart_qa.py` + `workers/report_generator_worker.py`
- **要点**：QA 规则分两级——发布级（标签全部可读/排序正确/五要素齐全）与草稿级；草稿级图不进正文，收入附录"补充图表"区并标注原因；报告头部如用户点名的图型缺失，明示"XX 图未达发布标准，原因：…"
- **验收**：A1-A4 修复后试运行：正文只出现发布级图；点名图缺失时有头部提示而非静默
- **依赖**：A1-A4
- **预估**：1.5 天

## B. 成本与时长（P0，可并行）

### B1. 反思轮数按链路预算
- **背景**：排行任务 3 轮反思 × 全量 LLM 调用 = 20.4 分钟；排行类 2 轮足够
- **改动**：`orchestrator_v2.py`（反思循环）+ `config.json`（system 段）
- **要点**：`system.reflection_budget = {"ranking": 2, "financial": 3, "general": 3}`（热重载已有）；按 `traceability_domain(goal)` 取预算；预算耗尽后缺口直接进 SUCCESS_WITH_ISSUES 附注
- **验收**：排行任务 ≤12 分钟；缺口仍如实披露（不静默放行）
- **预估**：1 天

### B2. 派生数字豁免（溯源指标修正）
- **背景**：平均换手率、占比等"由结构化数据可推导的算术值"被溯源检查扣分（55%<70%）触发无效重做
- **改动**：`acceptance_checker.py`（`check_number_traceability`）
- **要点**：数字分类三档：引用值（须溯源）/计算值（对结构化表做算术验证：均值/占比/求和误差 <0.5% 即通过）/模型知识（须标注）；details 文案按三档输出
- **验收**：任务5 报告重跑验收：计算值不再计入不可溯源示例；真实引用缺失仍扣分；test_p0 验收类零回归
- **预估**：1.5 天

### B3. LLM 端点账单监控告警
- **背景**：主端点余额耗尽只能在运行中靠 402 发现（本次切换 10 次）
- **要点**：`llm_client.py` 记录每端点 token/请求数台账（Redis 计数）；`/api/metrics` 暴露；余额类错误（401/402）首次出现即推送 notification + webui 顶部横幅；config 设月度预算阈值
- **验收**：模拟 402 响应 → 提交任务前 webui 出现告警横幅；metrics 可查各端点消耗
- **预估**：1 天

## C. 会话与状态（P0，可并行）

### C1. 会话持久化
- **背景**：会话存 webui 内存，重启全员掉登录（一次试运行被迫重登 4 次）
- **改动**：`web_ui.py`（`_sessions`）
- **要点**：会话落 SQLite（token/用户/角色/过期时间），启动时加载未过期会话；token 清理任务随写入顺带执行
- **验收**：登录 → 重启 webui → 刷新页面仍登录态；过期会话被清
- **预估**：0.5 天

### C2. 图表管线模块抽取（架构预备，随功能走）
- **背景**：图表逻辑散在 chart_assembly 常量 + orchestrator 调用点，改一处要同步两处（A1-A6 正在触及）
- **改动**：新建 `charts_pipeline/`（specs/qa/render/inline 四模块），orchestrator 改为薄调用层；行为零变化纯搬家
- **验收**：test_delivery_chain 176 测试零回归；`orchestrator_v2.py` 行数下降；A 组改动全部落在新模块
- **依赖**：建议在 A1-A4 完成后做（避免合并冲突）
- **预估**：2 天

## D. 日报 MVP（P1，依赖 A6+B1）

### D1. 日报定时任务产品化
- **改动**：`scheduled_jobs.py` + config 模板
- **要点**：内置"每日 A 股活跃度日报"模板（goal 固化为已验证链路）；收盘后 16:00 触发；产物自动生成 share 链接；失败自动重试一次并告警
- **验收**：连续 3 个交易日自动产出日报；失败有 notification
- **预估**：1 天

### D2. 日报落地页
- **改动**：`web_ui.py`（share page）
- **要点**：TOP3 结论卡片（领涨/领跌/最活跃）置顶；五要素图表区；数据溯源区块（来源/采集时间/可溯源率）；ranking.csv 下载按钮；尾部"生成同款报告"入口；全页保留免责声明
- **验收**：无登录可访问；移动端可读；单页 LCP <2s
- **预估**：2 天

### D3. 分发通道（最小版）
- **改动**：新 `notify_channels.py`
- **要点**：日报生成后 webhook 回调（企业微信/钉钉/自建 URL 三选一即可）；邮件备份；发送失败不影响任务状态
- **验收**：webhook 通道真实送达一次样例日报
- **预估**：1.5 天

### D4. 数据合规降险（Phase 1 内前置）
- **改动**：`adapters/`（sina/eastmoney 抓取层）
- **要点**：请求限频（≥3s/次）+ UA 标识 + 来源标注强制；adapter 接口留"官方数据源"切换位（环境变量切换实现类）；文档记录数据来源清单与用途
- **验收**：抓取层有限频；换官方源只需改配置不改业务代码
- **预估**：1 天

## E. 溯源页（P1 尾部，依赖 B2）

### E1. 数据溯源报告页
- **改动**：`web_ui.py`（报告路由）+ 前端 ReportViewer
- **要点**：验收器输出转译为用户语言三档表（引用值 N 条可溯源/计算值 K 条已验证推导/模型知识 J 条已标注）；每条计算值展示推导式；死链列表单独列出
- **验收**：任意历史报告可打开溯源页；三档数字与验收器内部一致
- **预估**：2 天
