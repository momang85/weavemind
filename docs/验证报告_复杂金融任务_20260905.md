## 二、运行时 Bug 清单（按优先级）

### P1 — 内容质量破坏性

**BUG-1｜多实体提取产出垃圾实体，结构化财务污染报告**
- 复现：`_extract_companies(任务1 goal)` → `['经营基本面', '新能源', '所有关键']`（已用 task_classifier 直接复现）
- goal 中显式写有"宁德时代（CATL, 300750.SZ）"却未被提取；"新能源"（来自"LG新能源"）被当公司名
  送 `resolve_company` → 东方财富 suggest 返回**国新能源（600617，燃气公司）**
- 后果：financials.json 装载国新能源财务，报告出现"子公司国新能源A股业务营收171.98亿"、
  "毛利率从9.54%降至7.4%"（国新能源口径冒充宁德时代口径）等荒谬内容
- 根因：`task_classifier._is_valid_company_name` 接受任意 2-6 中文片段；对比拆分不要求名称紧邻"对比"触发词；
  显式股票代码模式（`（..., 300750.SZ）`）未参与提取

**BUG-2｜financial_trends 图表装配：两实体数据拼接成一条趋势线**
- 文件：`ui-ec56fb8a67/project/financial_trends.png`
- 营收子图把国新能源（171.98/164.45/153.61 亿）与宁德时代（4237.02 亿）接成同一条序列，
  y 轴被拉爆、前三点压平不可读
- 年份口径错位：2025 年报数据画在 x=2026
- make_charts 模板 `ax.set_title(f"{mname}（亿元）")` 硬编码单位 → "毛利率"子图单位错标"亿元"且画的是毛利润绝对值
- 子图标题与上一子图 x 轴标签互相重叠（缺 tight_layout/间距）
- 另：chart_1.png 与 chart_2.png 数据完全重复（图表去重缺失）

### P2 — 功能缺陷

**BUG-3｜引用文本与 URL 不一致 + 附录 raw JSON 直出**
- 渲染报告引用[1]：文字"东方财富数据中心-国新能源财务数据"，URL 却是 `code=SZ300750`（宁德时代）
- "研究内容（检索/摘要）"附录直接贴 raw JSON（未格式化），且中间出现
  `[已过滤可疑内容：命令注入]` 过滤痕迹——注入过滤器对 JSON 片段误判，破坏内容完整性

**BUG-4｜make_charts.py 模板空序列崩溃**
- `make_charts.py:151 best = max(by_unit.values(), key=len)`：`bar_market` 过滤后为空时
  `max()` 抛 `ValueError`（任务2 日志实锤）→ 该任务丢一张图，`by_unit` 分支缺空守卫

**BUG-5｜图表 spec 单位混装，chart_qa 未拦截**
- 任务2 chart_1：上证综指区间（3450 点）与沪深300/恒指市盈率（11.8/8.5 倍）同轴柱状图，
  市盈率柱高度≈0，图不可读。图表 QA 应有"同图单位一致性"检查

**BUG-6｜验收检查器精度：来源声明误报**
- `_extract_source_claims` 正则 `(?:数据来源|来源|...)\s*[：:]?\s*([^。；\n，,|]{2,60})`
  会捕获表格分隔线（`------------------`）、费率数值（`0.60%`）、引用编号（`[1]`）等非声明片段 → 判"虚假标注"
- 真实抓取域名（100est.com=百优价值网、faxiangongchang.com=天下工厂、叩富网）不在域名→媒体名映射表 → 误报
  （检查器自己建议"补录域名媒体映射"，映射表维护是真实短板）
- 误报的直接代价：每任务触发"验收 fail 覆盖反思评分"强制重做，白耗 1-2 轮（任务2 因此多跑 ~8 分钟）

### P3 — 噪音/体验

**BUG-7｜worker brpop 超时误报 ERROR**
- `pop_task` 的 BRPOP timeout 与 Redis socket_timeout 冲突：search worker 每 ~2.5 分钟抛一次
  `redis.exceptions.TimeoutError` 全栈 ERROR（监控窗口内 13 次），随后自愈重新注册。
  无功能损害但污染日志告警面。修法：`socket_timeout > POP_TIMEOUT` 或捕获该超时静默续环

**BUG-8｜前端中途载入运行中对话不回放执行计划**
- 从历史页载入 PENDING 对话（?conv=xxx），Execution Plan 恒为占位文案，任务实际在跑却看不到任何步骤/进度
  （SSE 流不回放已发布状态）。观察性缺口

**观察项**
- History 页"查看报告"为 `<pre>` 纯文本预览（未渲染 Markdown），体验弱但属设计内
- 历史记录存在一条 8/30 的 goal 全乱码（`??A??5%...`）任务，为旧版编码问题痕迹
- 评测集自动生长正常：任务3 自动沉淀 case ag-010（10 条）

## 四、修复优先级建议

1. **P1** `task_classifier._extract_companies/_is_valid_company_name`：拒绝泛名词片段；
   对比拆分要求名称紧邻触发词；优先解析显式股票代码 `（..., 300750.SZ）`
2. **P1** 图表装配：按实体分组隔离序列（不同 entity 不拼同一条线）；年份取财报口径年；
   单位动态标注；同名数据图去重；子图间距修复
3. **P2** make_charts 模板空序列守卫；chart_qa 增加同图单位一致性检查
4. **P2** `_extract_source_claims` 收紧（排除纯数字/分隔线/引用编号）；补录域名媒体映射
   （100est.com、faxiangongchang.com、叩富网等），减少验收误报导致的无效重做
5. **P3** worker_base：`socket_timeout > POP_TIMEOUT` 或 BRPOP TimeoutError 静默续环
6. **P3** 前端 SSE 状态回放：载入运行中对话时请求一次全量状态快照
