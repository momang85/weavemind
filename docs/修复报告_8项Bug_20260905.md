## 逐项详情

### BUG-1 [P1] 实体提取：垃圾实体 + 显式股票代码未利用（task_classifier.py）
- **根因**：`_is_valid_company_name` 接受任意 2-6 字中文片段；`_extract_companies` 的对比拆分把
  "与LG新能源…对比" 拆出 "新能源"、"经营基本面"、"所有关键" 等垃圾；goal 中的显式股票代码
  "（CATL, 300750.SZ）" 完全未被利用 → resolver 把 "新能源" 解析成国新能源（燃气公司），
  其财务数据混入宁德时代报告（"子公司国新能源A股业务营收171.98亿"）
- **修复**：
  1. 新增 `_STOCK_CODE_RE`：`X（CODE）` 模式作为权威锚点，命中即只信它（`调研宁德时代（CATL, 300750.SZ）` → 宁德时代）；
  2. `_COMPANY_STOPWORDS` 增补 32 个泛化语境词（基本面/关键/格局/图表…）；
  3. `_extract_company` 也优先股票代码模式
- **验证**：任务1 goal → `companies=['宁德时代']`、`company='宁德时代'`（原为 `['新能源']`/`''`）；
  "对比宁德时代与比亚迪…" 等 14 个既有用例（含单实体、vs、分别、非对比句）零回归；
  `test_p0.TestMultiEntityPreload` + `TestPhase2ClassifierRouter` 14 测试全过

### BUG-2 [P1] 图表装配（chart_assembly.py + clean_data.py）
- **根因**：make_charts 模板 `ax.set_title(f"{mname}（亿元）")` 硬编码单位（毛利率也被标"亿元"）；
  未命名实体序列无图例；子图标题与 x 轴标签重叠；chart_1/chart_2 同数据重复渲染；
  clean_data 年份提取 `re.search` 取数值前**第一个**年份，把 "May 5, 2026 - …2025年实现营收…"
  的发布年 2026 当数据年（4237.02 画在 x=2026）
- **修复**：模板按指标行多数单位动态标注；未命名序列用来源域名兜底图例；`fig.subplots_adjust(hspace)` 修复重叠；
  RENDER_CHART_SCRIPT 增加 (label,value,unit) 指纹去重；clean_data 改取数值前**最近**年份
- **验证**：任务1 数据重清洗后 4237.02 → year=2025；financial_trends.png 重渲染：单位正确（营收/毛利润=亿元、
  毛利率=%）、图例完整、无重叠；同数据两份规格只渲染 1 张（SKIP 提示明确）

### BUG-3 [P2] 引用错位 + raw JSON 附录 + 过滤痕迹（report_generator_worker.py + orchestrator_v2.py）
- **根因**：报告守门逻辑把上游 raw 检索 JSON 整段贴进"研究内容（检索/摘要）"附录；
  注入过滤器 `_safe` 对含 `$(…)` 代码片段的检索 JSON 误判"命令注入"，替换成
  "[已过滤可疑内容：命令注入]" 后随附录进入报告
- **修复**：`_research_content` 新增 `_format_search_json`：检索 JSON 数组格式化为
  `- **标题**：[URL](URL) + 摘要` 清单；`_safe` 对可解析 JSON（结构化数据而非指令）跳过检测
- **验证**：构造检索 JSON → 输出为可读清单（无 `[{` 痕迹）；`detect_injection` 确认 JSON 确会误报、
  跳过逻辑生效（引用[1]错位为 BUG-1 污染的下游表现，随 BUG-1 一并消失）

### BUG-4 [P2] make_charts 空序列崩溃（chart_assembly.py）
- **根因**：模板 `best = max(by_unit.values(), key=len)` 在 `bar_market` 过滤后为空时抛 ValueError
  （任务2 日志实锤：图表生成失败丢图）
- **修复**：`best = max(...) if by_unit else None` + 空值走 SKIP 文案
- **验证**：任务2 项目重跑 → "SKIP 市场规模图：按单位分组后最多的仅 0 条（40 条总数据）"，
  进程正常结束（原为崩溃）

### BUG-5 [P2] 图表单位混装（chart_specs.py）
- **根因**：任务2 chart_1 把指数点位（3450）与市盈率（11.8/8.5 倍）画在同一数值轴，
  市盈率柱不可见；spec `unit="倍/点"` 本身就是混装信号，chart_qa 无单位一致性检查
- **修复**：`validate_spec` 两层检查：spec 级 unit 含 `/` 分隔 → 拒绝；data 行级 unit 不一致 → 拒绝；
  **散点图豁免**（量价散点 x=元/y=万手 双量纲为设计行为，回归测试保护）
- **验证**：任务2 spec → "unit 混合单位（倍/点）" 拒绝；行级混装拒绝；正常规格与量价散点均通过；
  `test_delivery_chain.TestRankingStructuredChain` 恢复通过

### BUG-6 [P2] 验收检查器误报（acceptance_checker.py）
- **根因**：`_extract_source_claims` 把表格分隔线（`------------------`）、费率数值（`0.60%`）、
  引用编号（`[1]`）、括号截断碎片（`称 X）`）当来源声明；真实抓取域名（100est.com=百优价值网、
  faxiangongchang.com=天下工厂、9fzt.com=九方智投）不在媒体映射表 → "虚假标注"误报，
  每任务白耗 1-2 轮强制重做
- **修复**：统一 `_claim_fragment` 过滤器（分隔线/纯数字/编号/括号失衡/碎片前缀/黑名单词），
  三处提取路径全应用；括号声明尾部右括号容忍；`_DOMAIN_MEDIA` 补录 10 个真实域名；
  别名组补 天下工厂/东吴证券/九方智投/百优价值网；新增无域名机构白名单（SNE Research/FRED）；
  `_known_sources` 增加拍平文本标题提取（URL 前行）+ 声明主体 ⊂ 已知标题子串匹配
- **验证**：三份真实报告 mislabeled **10/6/11 → 全 0**（同输入 A/B 对比）；
  `test_p0.TestAcceptanceChecker` 39 测试全过

### BUG-7 [P3] worker brpop 超时误报（worker_base.py）
- **根因**：`pop_task` 的 BRPOP 阻塞时长超过 Redis socket_timeout 时抛 TimeoutError，
  被任务循环当"unhandled error"刷整屏 traceback（监控窗口 13 次，每 ~2.5 分钟一次）
- **修复**：pop_task 单独 try/except，`type(exc).__name__ == "TimeoutError"` → 静默 continue
- **验证**：单测 4 连发 TimeoutError → 循环续跑、零 ERROR 日志；服务重启后线上观察
  （13:40:52 起）search worker **零**该类误报

### BUG-8 [P3] 历史载入不回放执行计划（web_ui.py + TaskConsole.tsx）
- **根因**：task_history 表只存 report，不存 steps/logs；前端 `loadConversation` 只加载消息，
  从不启动轮询/回放 → 载入运行中或已完成对话，Execution Plan 恒为空
- **修复**：后端 task_history 迁移新增 `steps_json`/`logs_json` 列，task_complete 时持久化
  （logs 截尾 200 条），`/task/<id>` 历史回退路径解析回放；前端 `loadConversation`：
  有 PENDING 消息 → `setTaskId` 交给轮询器实时跟踪；已完成 → 一次性拉取回放步骤树+日志
- **验证**：端到端——运行中对话载入显示 2/6 步骤实时推进；webui 重启（内存全清）后
  载入已完成对话，6/6 步骤 + 33 条日志从 SQLite 完整回放
