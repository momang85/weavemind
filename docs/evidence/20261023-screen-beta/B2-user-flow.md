## 结论（先说能到什么程度）

1. **三步式主流程在真实浏览器里可走通**：选数据来源与股票池 → 点示例条件填入规则 → 执行筛选 → 冻结结果（run_id + 结果哈希）→ 展开公司详情看四期财务图。本次走查全部用可点控件完成，截图见 `05-b2-step1-pool-and-preset.png`、`06-b2-result-trend-filters.png`。
2. **条件示例改成了 3 个「点了就能跑」的例子**，且阈值可改；例子只使用后端白名单里的 5 个字段，不再出现「示例点下去就被 400 拒绝」。
3. **通过/不通过的理由带阈值**：`毛利率 71.60% ≥ 70%；资产负债率 19.97% ≤ 60%：满足全部条件`（此前是 `毛利率 71.60%；毛利率 71.60%；资产负债率 19.97%` 这种重复裸读数）。
4. **公司详情 + 四期财务图**接的是已有事实链数据：柱=营业收入（亿元），线=毛利率（%），表格给出营业收入/毛利润/净利润/毛利率/经营现金流；缺 `net_profit_consolidated` 时表头如实写「净利润(含少数股东)」，不冒充归母。
5. **上传 + 保存/重开**：数据集上传后端能力已验证（B1 已走查）；本次在浏览器里用文件注入方式让页面自己发 POST 完成上传（原生文件选择器被扩展权限挡住，见「未验」）。预设「保存为预设 → 刷新页面 → 从已存预设载入」在浏览器里验证通过，规则/股票池/数据来源三件都还原。
6. **同一输入重复执行会复用同一份冻结结果**：`run_id 1d66f114…` 连续两次执行/复用同一 id，不重算、不生成第二份。
7. 结论边界：真实数据只有 2 家公司，**分页（>20 家）与原生文件选择器未验**；视觉是「向白金靠拢的自查版」，没有设计稿对照，也没有做跨浏览器像素比对。

### 真实浏览器走查（可复现步骤）

前置：隔离实例在 8083 跑着、`frontend/dist-screen-check` 是最新构建、管理员已把 `researcher` 加进 `screen.research_roles`。

1. 打开 `http://127.0.0.1:8083/screen`，用 `researcher / [已脱敏]` 登录。右上角显示「researcher 研究员（自助研究）」。

4. 点「执行筛选」→ 第 ③ 步出现「结果已冻结：run_id 1d66f114… · 结果哈希 754cf1b0f8bb…」，四态计数卡：通过 1 / 未通过 0 / 资料不足 0 / 合计 1。

## 反例（本次真实撞到的，都已处理或记录）

1. **同输入重复执行返回 409「历史结果已损坏（integrity=ok）」**：原因是我改了「通过理由」的输出文案却没升 `IMPL_VERSION`，同一身份（sha256(schema+impl+field_map+snapshot+rules_hash+period_policy+scope)）对应的内容变了，store 按 `FrozenCorruptError` 拒绝覆盖——**这是保护，不是 bug**：宁可 409，也不能悄悄把用户看过的冻结结果换掉。处理：把 `IMPL_VERSION` 升到 `stock_screen/1.2.1`（并补注释：输出变了必须 bump）。升版后同输入直接 200 且复用。**教训记录**：以后动 `stock_screen.py` 的任何输出文案/口径，必须同步 bump 版本，否则会在真实用户那里撞 409。
2. **示例 chip 用 `net_profit` 字段**：真实执行 400「未知字段「net_profit」」。白名单只有 5 个字段（revenue_growth / gross_margin / operating_cashflow / debt_ratio / cashflow_coverage），示例必须是「能跑通的例子」，已替换。
3. **百分比规则带 `unit:'%'`**：400「百分比字段的阈值不带单位（单位固定 %）」。前端 `rulePayload` 对百分比字段不传 unit，验证脚本也照此发。
4. **原生文件选择器打不开**：扩展未开「允许访问文件网址」时 `webbridge_upload` 报 `upload needs Chrome's per-extension file access`。绕过方式：页面内注入 `File`/`DataTransfer` 到自己的 `<input type=file>`，由页面代码自己发 POST（这条路径与用户点选文件后完全一致，除了选择动作本身）。**未验**：手点系统文件对话框。
5. **`webbridge` 长 `evaluate`（含 `setTimeout` 等待）会超时**：页面在后台时定时器被节流，30 s 工具超时。改法：所有页面内脚本保持同步，节奏用 shell `sleep` 控制；这属于自动化工具限制，不是产品缺陷。

## 未验（明确不当作已验）

1. **分页**：真实数据只有 2 家公司，`显示更多（还剩 N 家）` 在有 >20 家时才出现，**没有真实数据能触发**；未用合成数据「凑」这一条，如实记为未验。
2. **原生文件选择器**：见反例 4，只有系统对话框未验，上传链路（POST → 落库 → 目录刷新）已验。
3. **跨浏览器/响应式**：只在当前 Chrome 窗口（2549×1326 截图）看过；未测 Firefox/Safari、未测窄屏。
4. **视觉验收**：没有设计稿，只有自查清单；「白金」是方向，不是像素级对照结论。
5. **`net_profit_consolidated` 分支**：现有缓存只有 `net_profit`，图表回退分支是代码路径 + 单元测试，真实数据没走到「归母」表头。
