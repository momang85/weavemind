# 试用脚本：选股研究 Beta（内部走查版）

用途：给**第一次用这款产品的人**一份可以照着念的脚本，也作为内部走查的记录底稿。
适用版本：`stock_screen/1.2.1`，前端构建 `frontend/dist-screen-check`（20:18 构建，`index.html` sha256 前 12 位 `b416e5739440`）。
适用范围：A 股非金融公司、公开披露财务数据、确定性筛选。**不做回测、不给目标价/评分、不调用模型。**

---

## 0. 谁需要先做什么（只有一次）

| 角色 | 要做的事 | 怎么确认成功 |
|---|---|---|
| 管理员 | 把试用账号的角色设成「研究员（自助研究）」（设置 → 用户 → 角色），或在配置 `screen.research_roles` 里加入该角色 | 该账号登录后，选股页顶部没有「只读账号」横幅 |
| 试用者 | 用管理员给的账号登录 | 右上角显示角色「研究员（自助研究）」 |

若显示「只读账号：可看、可比、不可执行」：说明权限还没开，**不要继续第 3 步之后的操作**，先找管理员。

## 1. 打开选股页（约 5 秒）

左侧「可解释选股」。页面分三步：选范围 → 选条件 → 看结果。先别急着点，读一眼顶部一句话说明。

预期：能看到股票池目录、资料截止日（默认今天）、条件区（默认一组「高毛利低负债」示例）、以及「还没有筛选结果」。

## 2. 选范围（约 1 分钟）

1. 数据来源选「内置真实披露缓存」（2 家公司：洋河股份、三一重工）或你自己上传的 CSV 数据集；
2. 勾选 1–3 家（先少一点，便于逐条核对理由）；
3. 资料截止日保持默认即可。

预期：右侧显示「已选 N / M」。

> 自己上传 CSV：点「上传数据」，用页面的模板列名（17 列），单位写「元」，年度行 `period` 用 `YYYY-12-31`。
> 上传成功会显示数据集名称、行数、文件指纹；页面对用户上传数据始终标「未独立核验」。

## 3. 选条件（约 1 分钟）

点一个示例条件（如「高毛利低负债」），或自己加 1–2 条：

- 毛利率 ≥ 70（百分比字段**不填单位**）
- 资产负债率 ≤ 60
- 需要金额时（如经营活动现金流净额）才选单位：元 / 万 / 亿

预期：条件卡片上直接显示中文口径；填错会给中文提示（例如「百分比字段的阈值不带单位」「未知字段」），不会崩。

## 4. 执行筛选（约 1–5 秒）

点「执行筛选」。

预期：几秒内出现结果，顶部有 `run_id`、结果哈希、数据来源与「实际评估期」。同一输入重复执行会复用同一份结果（提示「复用」），不会重复计算。

失败时：
- 「只读账号不能执行」→ 回第 0 步开权限；
- 「实现版本已变」→ 旧结果只能查看原版，请重新执行生成新结果；
- 卡住超过 10 秒 → 刷新页面重试，并把时间点记下来。

## 5. 看结果，逐条读理由（约 3–5 分钟）

结果分三组：**通过 / 未通过 / 资料不足**。

- 点开任意一家公司，看每一条条件的中文理由（例如「毛利率 71.60% ≥ 70%：满足」）；
- 展开「公司详情」看四个年度的收入、毛利率走势（图是本地渲染，不联网）；
- 「资料不足」不是「不通过」：它表示这条读数缺失或冲突，界面会写缺什么。

要问自己的一句话：**这条理由，我能不能拿原始年报核对？** 核对不了就记下来，这比「结论对不对」更重要。

## 6. 留下来（约 1 分钟）

在结果行点「加入清单」，回到页面下方「我的研究清单」写一句备注（≤ 500 字），失焦即保存。

预期：刷新页面后清单和备注都还在；备注只在本账号可见。

## 7. 带走条件 / 复用条件（约 1 分钟）

1. 第 2 步点「导出模板」→ 得到一个 JSON，只含条件、期间策略、版本、说明；**不含**股票池、备注、结果、账号；
2. 点「导入模板」选别人给的 JSON → 先出预览（几条条件、期间策略、版本差异警告）→ 点「应用这些条件」只填表单，**不会执行**；
3. 要真正跑，仍需自己点「执行筛选」。

## 8. 看成本（约 30 秒）

页面下方「成本与请求」展开：执行请求 / 确定性计算 / 复用 / 模型调用 / 数据准备 / 预览 / 出站抓取 / 外部费用。

预期：模型调用与出站抓取为 0；外部费用显示「未知（无报价）」。**没有花模型钱 ≠ 没有成本**，页面已这么写。

## 9. 资料更正后再看一次（约 3 分钟，可选）

1. 上传一份更正后的 CSV（例如某年毛利率改了、或某期披露缺失）；
2. 用同样条件再执行一次 → 得到新 `run_id`；
3. 历史结果里选「旧的」和「新的」→ 点「对比这两份」。

预期：显示「谁进、谁出、谁读数变了」；条件没变而数据变了，会明确写「条件未变，输入变了——这解释的是数据更新的变化，不是筛选条件的效果」。读数缺失的那家会变成「资料不足」，不会被当成 0 或直接判不通过。

## 10. 结束时请记下（给我们）

- 哪一步卡住了、卡了多久、页面当时显示什么；
- 哪条理由你看不懂或无法核对；
- 你是否找到了「这家公司能不能投」的答案——如果找到了，请写出是哪一句让你这么想（我们要检查是不是产品误导了你）。
