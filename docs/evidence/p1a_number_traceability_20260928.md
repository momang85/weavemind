## 二、根因（四处，逐条实测）

### 1. `_norm` 把空白删掉 → 无单位大数**全部**匹配失败（B 类）

```python
_norm("139,076.05 166,154.73")  →  "139076.05166154.73"      # 两列数字粘成一个 token
_bare_match("139076.05", 上面那串) → False                    # 后随 "1" → 词边界不成立
```

披露表是**相邻两列连排**，去空白必然粘连；而 `_bare_match` 靠词边界防空匹配。
实测 `139,076.05` / `28,248,295,829.62` / `628,001,163.94` / `45,594.72` /
`158,834.29` … 在快照里**全部逐字存在（带千分位）**，却全部判"不可溯源"。

**修法**：新增 `_bare_norm()`（只去千分位、保留空白），无单位分支改用它。

### 2. 定位元数据被当成内容数字（A 类）

"（字符 9536-9573）"里的两个数被抽成"需要溯源的财务数字"，还进了"不可溯源示例"——
读起来像报告里有查不到出处的数字，其实是**我们自己的定位串**。

**修法**：`locator_metadata_spans()` 圈出标注区间（字符区间 / `api_chunk` / 页码 /
18 位信用代码），区间内的数字**不进分母**；`metadata_numbers()` 单列把被排除的数报出来，
明细里写明"定位元数据 N 个不计入分母（…）"——**分母与支持分别列账**。

### 3. 底稿算出来的数，不在任何溯源源里（C 类）

`check_number_traceability` 只认外部抓取源（search/fetch/clean/financials/structured）。
而 `-33.43亿元`、`69.37%` 这类读数**既不逐字出现在披露里**（是两次相除的结果），
也不在东财结构化数据里——它们是**底稿**（`project/working_paper.json`）算的：

```
net_profit_change  | 2024年较2023年 | -33.43 亿元 | formula="66.73 - 100.16，输入 fact-addeafb… / fact-70eca7c…" | derived_from=2
cashflow_coverage  | 2024年          | 69.37 %     | formula="46.29 / 66.73 * 100，输入 fact-bb258430… / fact-addeafb…" | derived_from=2
```

**修法**：新增来源通道 `workpaper_rows` / `workpaper_derived` / `located_facts`，
从**本次任务自己的**底稿与叙事证据构建，准入条件是硬门槛（不是装饰）：

- 底稿**明细行**：必须有 `fact_id`，且有 `source_locator`/`source_url`；
- 底稿**派生行**：必须**同时**有非空 `formula`（算式）与 `derived_from`（输入 fact_id）
  → "它自己可复算、且指得回披露"；
- 叙事证据事实/派发行：必须有 `locator`（或写明输入的 `formula`），定位挂在输入行上。

**反自证**：命中这三条通道记 **`计算`**，不记 `引用`（`cited_count` / `computed_count`
分开输出，且 `verified=False`）。"自己算的数"不得冒充"外部来源引用"。

### 4. 量纲/小数位/符号的写法差异（D 类）

同一个数在正文与底稿里写法不同，被当成不同事实：

| 正文写的 | 底稿/事实里的 | 说明 |
|---|---|---|
| `282.48亿元` | `28248295829.62 元` | 元→亿元 |
| `0.999亿元` | `99854764.34 元` | 两位舍入会变成 `1.00亿元`，要用三位 |
| `下降 42.50 亿元` | `-42.5 亿元` | 符号由正文方向词承载，抽取时已剥离 |
| `24.47亿元` | 697.92 − 673.45 | **两期差额**，底稿只给水平值 |
| `61.2%` | `61.2 %` | `_scale_forms` 原来只生成 `61%`/`61.20%`，漏掉写作本身的小数位 |
| `每 1 元净利润对应 0.612 元` | `61.2 %` | 百分比↔倍数 |

**修法**：`_scale_forms()` 生成 元/万元/亿元 × 2~4 位小数 + 千分位 + `:g` + 正负号两侧 +
百分比↔倍数；两期差额按**同指标、量纲相同**的两行相减，差额进
`workpaper_derived`（记"计算"）。

## 四、残留 22 处：不掩盖，逐条说清为什么没修

| 残留 | 处数 | 为什么不修 |
|---|---|---|
| `0.612元` / `0.694元` | 2 | 正文把覆盖 `61.2%` 改写成"每 1 元净利润对应 0.612 元现金"——**底稿没有这个读法**。要认它就得在通用换算里塞进"覆盖率→倍数"的口径知识，宁可留缺口 |
| `378003` | 1 | 正文**把数字截断**了（`378,003.……（节选）`）；截断的数字本身就不该判"可溯源" |
| 其余 19 | 19 | **`_promotion_subject` 的既有误判**（见下）——不是本轮改动引入的 |

### 未修但已定位：`_promotion_subject` 把中文散文当成公司名

```
_subject_of("需进一步取得利润表分项明细方可解释")  →  "需进一步取得"      # 不是公司名
_MEDIA_TOKENS 含单字"报"  →  "洋河股份合并报表口径下的…" 被整条丢掉
```

于是"报告侧主体"取成一个散文前缀、"来源侧主体"是真公司名（`洋河股份`），
`_subjects_conflict("需进一步取得", "洋河股份")` → **True** → 本可溯源的数字被否。
实测这类被否命中 **56 处**（底稿派生通道 25 / 已定位事实通道 14 / 快照 9 / 底稿明细 6 /
financials 2）。

**本轮刻意不动**：这是**跨公司同值**那道护栏（架构复核 P1）的判据本身，
改它必须单独一批、带语料级回归。现状方向**偏保守**（少数诚实命中被否），
不会把编造的数字放过去。已把实测证据写进 `_promotion_subject` 的注释里。
