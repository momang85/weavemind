## 1. 分析保留：从"按标题整节删"改为**块级判断**

旧规则：标题命中 `_DUPLICATE_SECTIONS`（含"关键数据/核心指标/财务对照/图表/数据时效"）
即整节丢弃。实机后果：模型把同比解读写成"三、核心指标两年对比与逐项解读"，被整节删掉——
交付稿的分析一节只剩 214 字（标题 + 口径声明）。

新规则（`_analysis_section`）：
- **装配器逐字生成**的小节（参考来源/资料来源/数据来源/参考文献/免责声明）整块丢——
  这是可证明重复；
- 其余小节只丢**非散文行**（模型自写表格、图片、来源清单行）；标题与散文一律保留；
- 块内没有散文（只剩表格/图）才整块丢——"标题里有核心指标"不再是删除理由。

## 2. "有分析"的最低要求（D2）

`analysis_coverage(text)`：至少一项**实际数据观察**（有指标 + 数值 + 单位的断言），
且文中出现意义/局限/边界/需核查一类表述；标题、口径声明、免责声明都不算。
读数进结构对象 `analysis_quality`；不达标时进风险清单（kind=`analysis_quality`），
点名缺"实际数据观察"还是缺"意义或推断边界"，并给出要补的材料——不靠加长正文掩盖。

## 3. 同版投影（D2）：面板按**当前采纳版本**重建

问题（阶段 D 前置审查 P1）：采纳正文 `fde2f2e9`，而 `report_structure.json` 属于装配候选
`8b23aad3`——面板把候选稿的发现摆在当前稿首屏，只靠一句"绑定版本不一致"提示。

实现（`web_ui._projection_for_version` + `_research_payload`）：
- 采纳版本与文件结构不同版时，按**采纳正文**重算结构（`build_structure`，确定性、离线），
  绑定采纳版本号后作为面板数据；结果按 (task_id, version_id) 进程内缓存（只留最近 8 条）；
- 重算不了（缺底稿/契约等）→ `projection.rebuilt=false` + 原因，并**清空版本相关的块**
  （发现/缺口/证据/主张），页面显示"面板未展示：当前版本的结构未能重建"；
- 同版时不重建，标 `same_version`；
- `projection` 始终带上 `for_version` 与 `file_version`，可审计"面板描述的是哪一版、文件是哪一版"。

**实机读数（17:2x 重启后，浏览器 DOM + payload 双读）**：
`structure_version=fde2f2e9`、`structure_current=true`、`projection.rebuilt=true`
（`file_version=8b23aad3`）；面板显示
`· 面板按当前版本（fde2f2e9df1e）重建；文件结构属 8b23aad32cf1`，
旧的"绑定版本不一致…修订后需重新装配"提示随之消失（因为面板现在确实描述当前版本）。

**验收中发现并修掉的一个真缺陷**：缓存命中时 `_projection_for_version` 返回了结构 dict
而非 `(结构, 原因)` 二元组 → 页面第二次轮询解包报 `too many values to unpack (expected 2,
got 17)`（服务日志 17:23:19），`research` 整体变 None、**面板消失**。已修（缓存命中返回
二元组）并补回归测试"连续两次取 payload"。
