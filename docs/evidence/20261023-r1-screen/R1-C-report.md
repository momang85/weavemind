## 2. 用户闭环如何落地

派单要求的一条用户闭环，在页面上就是从上到下四块：

> 选自己的股票池和资料截止日 → 确认少量财务规则 → 看带理由/缺口的候选 → 查看对应公司证据 → 保存并重开同一份结果

| 闭环环节 | 页面位置 | 具体行为 |
|---|---|---|
| 选股票池 + 截止日 | 第 1 步 Card | 复选目录里的公司（每行直接标出「N 行 · M 个年度期间 · 可用时点 a ~ b」）；不在目录里的代码可手输成芯片，并提示「目录里没有，执行后计入资料不足，不编造读数」；截止日 `input[type=date]`，默认取当天 |
| 先看输入 | 第 1 步「预览输入」 | 预览面板列出：来源身份（路径/行数/是否合成/文件 sha256）、每主体可用观察数、期间、口径、币种、单位、可用时点、`dataset_hash`、`gaps`/`conflicts`；被 PIT 规则排除的行逐条给理由（如「资料可用时点 2026-04-28 晚于截止日 2025-04-30：不纳入（不倒灌）」）；缺可用时点的行进 `pending` 提示而不是静默纳入 |
| 确认财务规则 | 第 2 步 Card | 字段下拉（5 个字段，每个带 formula 说明）、比较符、数值、金额类字段自动切换单位（元/万/亿）；「换个例子」可重置；至少一条才允许执行 |
| 看三态候选 | 第 3 步 Card | 四张统计卡（通过/未通过/资料不足/合计）+ 三段列表；每行显示评估期间、底稿哈希、每个字段的读数卡（值 + 计算公式）、以及本轮判定的理由文本 |
| 查看公司证据 | 行首「展开」 | 请求 `?run=&entity=`，面板标题写明「证据绑定这一份冻结结果：run_id … · 结果哈希 …」；每个读数给出 formula + 输入科目表（科目/期间/数值（含单位与口径）/可用时点/来源链接）+ 未解析输入 + 该主体被排除/待核验的行 + 来源文档清单 |
| 保存并重开 | 第 3 步底部 + 历史 Card | 每次执行都落一份冻结结果（`run_id` + `结果哈希`）；「查看原版」= GET 读回同一份（不重算），顶部横幅说明「正在查看原版结果（时间）… 要看当前数据下的最新筛选，请点『用当前数据重新筛选』」；「用当前数据重新筛选」= 用原版参数重新 POST 一次；历史结果表按时间倒序，可再次打开任何一份 |

三态语义在界面上被写死，避免"看起来都通过"：

- **通过**（绿）：全部规则满足；
- **未通过**（琥珀）：有读数但不满足，逐条写「毛利率 26.43% ≥ 70.0%：不满足」；
- **资料不足**（灰）：缺读数/冲突/待核验，**不并入未通过**；原因如「输入里没有该主体的观察：不编造读数」。

空态也带解释，而不是空白或"暂无数据"：

- 通过 0 家 → 「本次条件下没有通过的公司。这是筛选结果，不是「暂无数据」——见下方未通过与资料不足的明细。」
- 资料不足 0 家 → 「没有资料不足的公司：每家都有满足比较所需的读数。」
- 历史为空 → 说明执行后会生成什么、为什么不可变。

## 3. 「查看原版」与「重新筛选」为什么不混

| 动作 | 请求 | 会不会重算 | 界面后果 |
|---|---|---|---|
| 查看原版（行内/历史行「打开原版」） | `GET /api/screen/run?id=` | **不会**（只读盘上 `run.json`） | 结果区显示冻结横幅 + 原始时间戳；表单回填为**原版参数**，便于对比 |
| 重新筛选（「用当前数据重新筛选」） | `POST /api/screen/run` | 会（同一身份则复用） | 若哈希一致 → 提示「输入、规则、截止日都与历史某次完全相同（哈希一致）：直接打开那份原版（xxxxxxxx…），未重算。」；若产生新结果 → 提示「已生成新结果（旧结果原样保留，可在历史结果里重开）。」 |

这两条提示都来自实测（`09-reuse-same-frozen-run.png`），不是设计稿文字。

## 8. 本阶段发现并修掉的 3 个问题

1. **渲染崩溃**：`preview.excluded`（对象数组）被当数字渲染 → `Minified React error #31`。
   修法：为 `ExcludedRow/PendingRow/PreviewEntity/RunEntity` 定义显式类型并逐条渲染原因（不是改成 `[]` 了事）。
2. **行内理由图标语义错**：通过的公司也挂琥珀三角。修法：`pass` 行用绿勾，其余用琥珀三角。
3. **复用提示漏报**：刷新页面后重复执行同一输入，服务端 `reused=true` 但界面不提示（原逻辑要求"和当前正在看的这份相同"）。
   修法：区分「复用当前这份」与「命中历史某份原版（哈希一致）」，各自给准确文案。

## 10. 预设与「过期」提示（§3-D 补齐）

### 10.1 预设（股票池 + 规则）

第 1 步卡片内新增一行「预设」：下拉选择已存预设、名称输入框、「保存为预设 / 更新预设 / 删除预设」，
下方一行状态文案（载入/保存/删除结果）。三点纪律写进了文案与实现：

1. **载入不等于执行**：载入后只回填池、截止日与规则草稿，提示「规则需你确认后才会执行」；
2. **预设不绑定结果**：提示「它只记住池与规则，不绑定任何结果」；
3. **删除不动历史**：删预设只删偏好文件，已冻结结果照旧可开（`R1-C-http-walk.log`：runs 6→6）。

截图：`screenshots/10-preset-saved.png`（保存后）、`screenshots/13-preset-loaded.png`（载入后池与规则回填）。

### 10.2 原版「过期/不可重算」

`GET /api/screen/run` 本来就返回 `impl_version`、`field_map_version` 与 `source.sha256`，
前端拿它与当前 `/api/screen/fields`、`/api/screen/pool` 的身份比对，不一致就在结果卡顶部出一条
警示（标题「这份原版与当前实现/输入不一致（只能查看，不冒充现状）」），逐条给原因：

- 实现版本变化 → 「这份由 `stock_screen/0.9.0` 生成，当前是 `stock_screen/1.0.0`。旧结果不会按新实现重算，只能查看原版。」
- 输入文件变化 → 「这份用的是 `4dc828ef0bea…`，当前缓存是 `ed5d48ddf31f…`。要看新数据下的结果，请『用当前数据重新筛选』。」

**原版内容不因提示而改变**：提示只是加一层警示，读数、哈希、证据仍来自冻结文件。

截图：`screenshots/11-stale-input-changed.png`（只输入变了）、`screenshots/12-stale-old-version.png`（实现 + 输入都变了）。
