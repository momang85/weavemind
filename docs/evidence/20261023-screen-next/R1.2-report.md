## 0. 一句话结论

用户现在可以**不写代码、不碰模型**地走完一整条闭环：下载模板 → 上传自己的 CSV → 在界面上看清这份数据的字段、期间、来源与「不是官方数据」→ 用它勾股票池 → 预览真实可用资料 → 执行冻结结果 → 逐条看读数来源 → 存成预设 → 关掉重开还回到**同一份数据来源**。

这一步之所以重要，是因为此前「用户的数据」只能靠改服务端缓存文件才能进来；现在是产品内的正常入口。三类来源（服务端官方缓存 / 用户上传 / 合成演示）在界面与服务端都分得开，上传**结构上无法自封官方**。

单测 173 项通过（59 + 57 + 30 + 27），真实 HTTP 走查 27/27。走查中修掉 **4 个真实卡点**（来源切换竞态、上传后界面永久卡在「上传中…」×1 类成因、预设不记来源导致重开静默换数据），逐条在第 4 节。R1.3（两份冻结结果对比、不可直接归因标注）尚未开始。

## 2. 三类来源怎么分开

| 来源 | 界面怎么写 | 谁判定 | 用户能否让它变成「官方」 |
|---|---|---|---|
| 服务端官方披露缓存 | 下拉项「官方披露缓存（服务端配置）（N 行）」；页头「数据来源：<缓存名>｜N 行｜官方披露缓存｜文件 sha256 …」 | 服务端按**配置路径 + 文件内不 synthetic / 不 user_provided** 判定 | 不能（除非改服务端文件，那是运维动作，不是产品内操作） |
| 用户上传（本批新增） | 下拉项「我上传：<名字>（N 行）」；页头「用户数据集：<名字>｜N 行｜**我上传的数据（用户提供，未独立核验）**」；结果横幅「本次结果包含用户提供的数据」 | 服务端：凡从 `datasets/` 读出的数据一律 `user_provided=true, official=False` | 不能。CSV 里塞 `official=true` 列 → 400「未知列」（不静默忽略） |
| 合成演示数据 | 页头「合成演示数据」 | 服务端文件内 `synthetic:true` | 上传无法声明 synthetic，因此上传数据**永远不会**被当成演示数据，反之亦然 |

原则落地：**来源是服务端属性，不是文件自述**。这与「证据与底稿是可靠性底座」一致——用户可以提供数据，但「这是官方披露」这句话不能由上传者自己说。

## 4. 本轮发现并修掉的 4 个真实卡点

1. **换数据来源时，旧来源的响应会覆盖新来源的目录与标注。** 快速切两次来源时，先发后至的旧请求把「来源：合成测试导入」写回界面，而池子已经是另一份数据 —— 用户会拿 A 的目录读 B 的来源说明。已加请求序号，只让最后一次请求落地（`StockScreen.tsx` `poolSeq`）。这类「看起来一致、其实是两份数据」的问题比缺功能更危险。
2. **上传后界面永久卡在「上传中…」（成因一）：先清空 `input.value` 再读文件。** 浏览器会因清空而释放 `File` 句柄，`file.text()` 悬空 → 按钮永远转圈。已改为**先读文本、读完再清空 input**。
3. **同一现象（成因二）：读文件本身没有超时。** 即使不是上面的成因，读不动时用户也无从知道发生了什么。已给读取加 10 秒兜底：「读取文件超过 10 秒没有返回：请确认文件没有损坏，或先「下载模板」另存后重新选择」——等待要有终点。
4. **预设只记池与规则，不记数据来源 → 重开时静默换数据。** 同一份预设、看起来完全一样，却因为来源退回官方缓存而算出不同候选（官方缓存里没有的代码直接变「资料不足」）。已把 `dataset_id` 纳入预设：保存时校验数据集仍存在（不存在 → 400「不存在或已删除…不保存指向空来源的预设」），载入时若已删除则**明说不可用并请你重选**，绝不悄悄换源。回归：`test_screen_store.test_preset_remembers_dataset_source_and_refuses_dead_one`、`test_screen_api.test_preset_keeps_dataset_source_and_rejects_dead_one`。

（另有两处口径修正：页头来源标签原先直接显示机器名 `official_disclosure_cache`，改为「官方披露缓存（服务端配置）」并保留原文件标签；数据集 id 原先把文件名/显示名也纳入哈希，改名就换 id，已改为**只对数据内容寻址**，改名/换文件名仍是同一数据集。）

## 5. 可靠性边界（本批明确写死的）

- **身份**：`dataset_id = sha256(规范 CSV 数据体)[:32]`；只含数据，不含名字/文件名/上传时间。同内容 ⇒ 同 id ⇒ 复用，磁盘上不重复存。
- **上限不静默截断**：行数 > 5000 或字节 > 2 MiB 直接拒绝并说明，不截断、不丢行。
- **篡改不吃**：`rows.json` 被改动后重新读取或执行 → 报「哈希不一致」，不当作原数据继续算。
- **作用域**：数据集只在本账户可见；别人的 id 读不到（按「不存在」处理，不泄露存在性）。
- **损坏/不可用**：预设指向的数据集被删 → 保存被拒、载入明确提示；结果目录损坏 → 409 且磁盘字节不动（R1.1 已立，本批未改）。
- **写入**：临时目录 + fsync + rename，Windows 瞬时失败重试 6 次后回 `503 store_unavailable`（明确「未写入任何结果，可原样重试」）。

## 7. 明确没做 / 仍然缺的

- **不做**（本批红线）：自动联网采样、把上传数据当官方、后台定时抓取、外部通知、模型调用、付费数据源、自动调仓。全程 API 额度消耗 **0**。
- **没做**：数据集删除的界面入口（当前只能由运维删目录；删了以后预设会在保存/载入时明确拒绝或提示，不会静默换源）；数据集并发写的竞态测试；大文件分页/流式上传（现在是整体读取 + 上限拒绝）；字段级「模板填写说明」页（提示已在表单内，但没有独立帮助页）。
- **还没证的**：这份闭环在真实用户手里的完成率与耗时（本报告只有单机演示步骤与毫秒级等待，**不构成**「更好用」的结论）；「最合适个人投资者」是待验证目标，本批不做市场排名或效果承诺。

## 8. 与产品原则的对齐（§0）

- **吸收了同行的标配**，没因为它不独家就跳过：模板下载 + 上传自己的数据、可视化的字段/期间/来源确认、可保存复用的预设、结果与证据逐条对应 —— 这些是任何筛选工具都该有的东西。
- **差异化是结果不是门槛**：本批花力气的地方是「来源不可自封」「重开不换源」「上限不静默截断」这些不容易被看见的可靠性细节，而不是造一个独家功能。
- **不让用户承担工程复杂度**：用户只需填 CSV 与点按钮；列名错、数值坏、期间缺都有逐行中文说明；等待有毫秒级反馈与超时兜底。
- **不把产品缩成证据归档**：模板/上传是让用户用自己的数据完成研究任务，证据只是结果的一部分，不是产品形态。
