## 二、三种归因标签（面板顶部横幅）

| 触发条件 | 标签 | 横幅语义 |
|---|---|---|
| 规则 / 股票池 / 期间口径任意一项不同 | **不可直接归因** | 候选差异不能当作「条件产生了什么效果」，也不能跨这两份做连续比较；要先统一条件再比 |
| 只有资料截止日或数据来源变 | 条件未变，输入变了 | 解释的是「数据更新带来的变化」，不是「筛选条件的效果」 |
| 五项全同 | 条件与输入都没变 | 两份是同一条件的重放；读数差异只可能来自输入本身 |

条件卡片里，`数据来源` / `资料截止日` 不同只标「不同」，不抢「不可直接归因」的结论——结论统一由横幅给，避免同一屏两处说法不一致（这是本轮修掉的一处措辞矛盾）。

## 四、普通用户路径（选池 → 条件 → 结果解释 → 保存重开 → 回看变化）

| # | 用户做什么 | 会看到什么 | 卡点/等待 |
|---|---|---|---|

| 7 | 在两个下拉里选「基准（先的那份）」「对照（后的那份）」→ 点「对比这两份」 | 横幅定性（能不能归因）→ 五项条件对照 → 计数行 → 新进/退出清单 → 两份都在公司的读数前后值 | 同一份不能和自己比（会提示）；选不到两份时会提示先选 |

## 五、本轮修掉的卡点

1. **「对比中…」可能永远不回**：对比/原版/证据三处请求都套上 20 秒超时，超时给中文提示并可重试（`fetchJSON`）。
   实测触发过：浏览器标签页连接池卡住时，按钮会一直停在「对比中…」——这是普通用户最容易误判成「程序死了」的形态。
2. **「数据来源」不同被标成「不可直接归因」**：条件卡片原来对所有「不同」都写「不可直接归因」，与横幅的 `条件未变，输入变了` 冲突；
   改为只有规则/池/期间口径才写「不可直接归因」，来源与截止日只写「不同」，归因结论只在横幅出现一次。
3. **缺数被读成变化**：字段在一份里有、另一份没有时，原来只显示「（该份未评估此字段）」，容易被当成数值变化；
   补一句「这一项在两份里「有数/无数」不同，不是数值变化」。

## 七、边界（明确不做）

- 不建后台自动拉数、不常驻监控、不发外部通知、不造「该复查了」的假提醒；对比只在用户点的那一刻读本地已冻结文件。
- 不做自动调仓、不给买卖点、不把候选清单叫组合、不给综合评分或因果结论。
- 不重算任何一侧的结果：对比读的是两份已冻结的 `run.json`，不重跑筛选、不重算指标。
- 不做跨口径的「连续曲线」：期间不同只并列展示并标不可横比，不画趋势、不算 delta 排名。
- 模板导出/导入、模板分享（含私人池/备注/受限材料）本批只交字段白名单与导出格式/校验设计（见第九节），不实现导出。

## 九、规则模板导出/导入设计（派单要求「本批先交设计及字段白名单」，只设计不实现）

**设计目标**：让用户能把自己的「规则包」带走、给别人用，但**不带走**私人股票池、备注、受限材料和任何结果数据；也不做成公开收益榜。

**导出内容（只含规则，默认不含池）**
```json
{
  "schema": "weavemind.screen.rules/1",
  "impl_version": "stock_screen/1.1.0",
  "field_map_version": "1",
  "exported_at": "2026-10-23T18:00:00+08:00",
  "rules": [{"field": "gross_margin", "op": ">=", "value": 20}],
  "period_policy": {"mode": "uniform", "report_period": ""},
  "include_pool": false,
  "pool": [],
  "note": "只有规则与期间口径；不含股票池、备注、结果、读数或任何密钥"
}
```
- 默认 `include_pool: false`；用户显式勾选才带代码列表（**只带代码**，不带持仓、成本、备注）。
- 不带 `run_id` / 结果 / 读数 / 证据文件 / 用户身份 / 作用域 id / 密钥；文件名 `weavemind-rules-<时间戳>.json`，页面显示 sha256 前 12 位。
- 字段白名单随包写入 `field_map_version`；白名单外字段不允许出现在导出包里（导出前按 `FIELD_SPECS` 逐项过滤并报错，不静默丢弃）。

**导入校验（服务端，先校验再入表单，不自动执行）**
1. `schema` 必须是 `weavemind.screen.rules/1`；`field_map_version` 与当前一致，不一致给「字段口径已变：请在表单里逐条确认」而不是硬套。
2. 逐条：`field` 必须在白名单、`op` 必须合法、`value` 类型匹配（百分数字段不允许带单位）。
3. `period_policy.mode` 必须在 `PERIOD_MODES` 内；`pinned` 必须带 `report_period`。
4. 校验通过后**只填表单**，由用户自己点预览/执行；导入不触发任何筛选、不写盘、不联网。
5. 任何一条不合法 → 整包拒绝并给中文逐条原因（不做「部分导入」）。

**隐私与分享边界**
- 模板只在用户本机文件系统里流转（浏览器下载/上传）；服务端不落公共库、不做公开链接、不做收益榜。
- 上传的文件按「用户提供」处理，不因模板来源被标成官方；模板里的池若含受限材料代码，导入页会照常提示「不在目录里的代码计入资料不足」。
- 分享给他人 = 发文件，不经过服务端；因此不存在「谁的模板被谁看到」的权限问题。

**与预设的关系**：预设 = 本机偏好（含池与数据来源，保存后直接复用）；模板 = 可复制的规则包（默认不含池）。两者走同一条规则校验，导出不改变任何已冻结结果。

**本批不做**：导出/导入的实际实现、公共模板库、模板市场或收益榜。
