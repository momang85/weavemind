## C1-2 表头与数据列共享列网格

`report_pdf._draw_table_header` 原实现把各列名用两个空格**拼成一行**画在 `MARGIN_L + 4`，
而正文按 `MARGIN_L + c * col_w + 4` 逐列定位——实测正常场景第 1 页
"指标 2023 2024 口径 来源"全挤在左侧。现在表头逐列绘制，与数据行共用 `col_w` 与列起点；
跨页续画走同一个函数，续页表头与首页一致。

**确定性检查**：`report_pdf.pdf_table_grids()` 从内容流推出列位（"多数行都出现的 x"，
不依赖字宽估算——单元格换行与字形回退都会在同格内多画一段，但不改变列位），
判定三条**平台无关**的条件：① 表头横向跨度必须 ≥ 数据列跨度的 90%（拼接式表头把各列名
画在一个 x 上，跨度退化为 0，这一条直接抓住它）；② 表头格位多数（≥60%）落在数据列位上；
③ 首列仍从左边距 +4 起。

> 为什么改成"跨度"而不是"格数相等"：CI（Linux，DroidSansFallback）上字形回退把
> ASCII 与 CJK 拆成两段绘制，**同一单元格**会多出 x 位置，按"表头格数必须等于数据列格数"
> 判定会在 Linux 上误报不对齐（本地 Windows 字体不拆，两边结论不一致）。跨度与
> "多数落在列位"对拆段免疫：本地与 Linux 都通过，而拼接式表头在两端都判不对齐。
> 本地已用"把字体对 ASCII 的映射强制为 0"复现该拆段环境验证过。

自证有齿（`scenario_checks.TestOfflineScenarios.test_table_header_alignment_check_has_teeth`）：
渲染一份含长中文标题/负数/单位/年份列的表（`| 指标 | 2023年 | 2024年 | 口径 | 来源 |`，
含 `-46.29`）→ 5 列全部对齐；再把 `_draw_table_header` 换回旧写法 → 同一检查判
`aligned=False`。

## C1-3 导出完整性纳入验收（不再用页数/文字量冒充视觉通过）

`scenario_run` 的 PDF 判定拆成两块，名字如实：

- `pdf_parse`（**可解析性**）：页数、空白页、文字量。空白页判据已修——整页只有一张图的页
  不算空白（原先 loss/missing 场景各有一页"只有图"被判疑似空白页）。
- `pdf_export`（**导出完整性**）：`report_pdf.pdf_image_report()`（**画在页面可视区内**的
  图片数 vs 本场景引用图数、缺图占位数、尺寸异常）+ `pdf_table_grids()`（表头/数据列网格）。
  引用图数取自**本场景图表清单**，不是磁盘 PNG 数。

两个判定对所有场景**无条件**生效（`checks` 新增 `pdf_parseable` / `images_embedded` /
`no_image_placeholder` / `table_columns_aligned`）——缺图或缺列对齐时导出完整性直接失败。
`visual_verdict` 这个旧名已删除（`test_pdf_verdicts_are_named_honestly` 断言不得复活）。

## C1-3b 逐页看渲染页发现的两个新缺陷（已修 + 有齿回归）

只看"图数/页数"仍不够——把三份 PDF 栅格化逐页看（`scripts/pdf_visual_check.py --pdf`，
用 Codex 运行时自带 pypdfium2 的解释器），发现两处**只有看图才看得见**的问题：

**① 画布被撑爆的空白巨图（两张）**：`loss_mixed_units/chart_1.png` 1038×**144445**、
`missing_footnote_asof/chart_2.png` 1038×**121366**（正常图 1038×644）。根因链完整：

1. 同比三个值全是负的（-12.83 / -24.49 / -33.38），`render_bar` 无条件
   `ax.set_ylim(bottom=0)` → 上下限相等 → matplotlib 只发一条 warning 就"自动扩展"，
   坐标变换退化成奇异值；
2. 放在原始数据位置的数值标签被甩到画布外几万像素；
3. `bbox_inches="tight"` 把落盘 PNG 撑成高宽比 117 的空白图；
4. PDF 那边"成功嵌入"了它（页面资源里确实有 Image 对象），但变换矩阵把它画到页面
   可视区之外——页面上什么都看不到，而按"XObject 计数"的检查照样报"5/5 已嵌入"。

修法三层，各配自证有齿的回归：
- `render_bar` / `render_grouped_bar`：**只有存在正值**时才把基线钉在 0，全负时自动缩放 +
  零基线参考线（负值标签改为画在柱端内侧）；
- `chart_qa.canvas_aspect_issue()`：落盘后读 PNG 头判画布高宽比（上限 12），超限进
  `residual` → 该图 `grade=draft`（不再算发布级）；
- `report_pdf`：单页放不下的图（`dh > USABLE_H`）按缺图处理，留可见占位并写明尺寸异常；
  `pdf_image_report` 增加 `drawn_on_page` / `oversized`——只数"真的画在可视区内"的图，
  登记了对象但画到页面外的一律算缺图。

修后同一三份场景：页数 7/6/7（原 7/7/8），11 张图全部 1038×644，verdict 全 pass，
第 3 页从"一张巨图 + 大片空白"变成两张正常可读的图。

**② 表头错列**（C1-2）与**图注措辞**：表头已修；图注文字里 `…对比如何？ ； 两期核心指标…`
这种"问句 + 分号"的拼接仍显冗余，属 C3（精简成稿）范围，本轮不改。

## C1-5 现金覆盖条件文案收口

`facts.RATIO_CONDITIONS["cashflow_coverage"]` 原文说"仅当分子分母同为正时表示
『当期经营现金流高于归母净利润』"——正数之间仍需比大小，这句在正数区间是误导
（该句已随新 PDF 进入正文）。改为：同为正时**按数值判低于/相当/高于**（相当=差 0.5
个百分点内）；任一为负或分母为零时**不套覆盖解释**。

主结论（`report_brief._findings`）此前已是三分支（低于/相当/高于 + 负值/零值单列），
本次补定向检查：69.37%（低于）、100%（相当）、107.23%（高于）三个读数各自落在正确分支，
负净利润/负经营现金流/零分母走"不表示利润有现金支撑 / 不可算"，且条件文案不再声称
"同为正即高于"。
