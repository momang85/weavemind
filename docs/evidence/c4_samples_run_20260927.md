## 4. 本批发现的缺陷（按影响排序，均未修）

- **(a) 派生金额拖垮溯源率**（样本①验收 fail 的直接原因）：
  不可溯源示例里的 `33.43亿元 / 38.01亿元 / 4.58亿元` 恰好是**派生量**
  （Δ归母净利润 / Δ毛利润 / 毛利线以下净额）。它们由已绑定的两期事实相减得到，
  却按"无引用"计入不可溯源，把溯源率压到 52%。同时 `9536`、`9573` 这类
  **页码/编号被当成财务数字**计入分母（406 个里含这类噪声）。
- **(b) `web_search` 假成功 + 指纹重建死循环**：同一条查询重试 4 次、每次都 `SUCCESS`，
  最终仍判"外部检索失败"，且**没有产出任何候选 URL**。要么"SUCCESS"判据太宽，
  要么指纹重建没有真正换查询（4 次 dispatch 的查询串完全相同）。
- **(c) `/actionable` 归因错误**（C3 面的缺陷，我自己的活儿）：失败任务的
  `message` 写"任务明确失败：**code_sandbox 不可用（docker）**→ 看健康页"，
  而真实原因是检索/材料与验收门槛，**正确动作应是"补材料"**。
  环境健康盖过了任务自身的失败原因。
- **(d) 补材料闭环不完整**：证据/结构/底稿都重做了，但**正文重生成没有任何入口**
  （代码里只有 `requires_narrative` 与一条"待授权"待办），所以覆盖提升无法闭环。
- **(e) 取件依 URL 而异**：同一份内容，镜像站 URL 只拿到 985 字节被判"扫件"，
  官方站 URL 拿到 4.70 MB 正常解析 → 取件层需要区分"下载失败"与"PDF 无文本"。
- **(f) embedding 不可用**（`MODEL_CAPABILITY_NOT_SUPPORTED`）：记忆检索降级，未修。
