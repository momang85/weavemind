**台阶日＝除权除息日**（这是复权口径可解释的证据，不是猜的）：

- `002304`：2023-06-21、2024-06-26、2025-01-27、2025-06-27、2026-06-30

**判据为什么要带容差（这是本轮修掉的一个假警报）**：前复权价在源侧已四舍五入到 0.01，比值因此带
`0.5×10⁻² / 当日不复权价` 量级的舍入噪声（本题约 1e-4）。不带容差时"台阶数"会算成 **843 个**（把舍入噪声
当台阶），判据本身失效。容差**逐日**按当日不复权价算，不用全局常数；修正后台阶数落到 **5 个**，与年度
分红次数一致。原始比值有 671/804 个不同值 —— 那只是 2 位小数舍入噪声。

**另一个实测约束（改了采购判断，见采购决策单）**：tushare 免费档 `adj_factor` **限频 1 次/分钟、1 次/小时**。
"复权价可自算"这件事**单点成立、批量不成立**；抓取脚本已改为"因子取不到也不丢日线"（逐行留空 + 记原因），
不把已拿到的 908 行日线一起扔掉。

## 二、Y2a 算子：`event_returns_v1`（`quant_research/event_returns.py`）

**为什么单独一族算子**：财报算子的输入是 `Observation`（带币种/量纲/归属层/报表范围身份），行情载荷只有
逐日价格 + `available_at` + 复权口径。把行情伪装成 `Observation`，会让"同一性校验"在无意义字段上通过——
等于把校验做成摆设。所以行情用**自己的输入契约**：`input_kind = market_history@<dataset_id>`。

| 纪律 | 落成什么（可被检查的字段） |
|---|---|
| 防未来函数 | 切片只取 `date > 事件日`；读数带 `available_at_upper_bound` 证明"当时拿得到" |
| 口径必须写明 | `adj_basis` 空 ⇒ `unavailable`；标的为**不复权**⇒ **默认拒给**（`allow_unadjusted=True` 才降级为 caveat） |
| 基准对齐 | 按**日期**对齐；基准缺该交易日 ⇒ 该点 `excess_return=null` 并列入 `benchmark_missing`，**不补 0、不前值填充** |
| 超额口径 | **几何** `(1+个股)/(1+基准)−1`，不是算术差（测试锁住这条） |
| 锚点不假装是测量 | `t-1` 的收益留空 + 注明"锚点（基准点）"——填 `0.00%` 会被读成"事件日无波动" |
| 重叠不去重就不聚合 | **同标的**窗口重叠的事件**仍出单列读数**，只是不进聚合；**跨标的不算重叠** |
| 样本不足不产统计量 | n<2 不给均值/中位数（显式 `note`）；n<3 不给"胜率/上涨占比"类比例字段 |
| 许可随读数走 | `delivery_eligible=false` + `delivery_block_reason`，写进 limits |
| 可复算 | `input_fingerprint` ＋ `reading_hash`；`replay()` 逐点比对并报差异，**不改写旧读数** |

## 四、纠错（本轮自查发现并锁住）

1. **事件日必须取证据文档里的公开披露日**。上一轮口算用的洋河 2024 年报事件日是 `2025-04-28`，
   而证据文档（`y1_002304_goal_realization_20261005.md`）记录的是 **2025-04-29**。已改为 04-29，
   并加测试 `test_uses_verified_disclosure_dates_not_guessed` 锁住"不得回退成旧口径"。
   —— 这不是口径差异之争：事件日错一天，t0 的整段读数就错一个交易日。
2. **重叠判定不能跨标的**。第一版把"两家公司同期披露"也判成重叠，直接把样本从 3 砍到 1。
   正确语义是"同一段价格路径被数两次"才排除 ⇒ 改为按标的判定，跨标的只在字段里说明。
3. **锚点收益不能填 0.00%**（见上表纪律）。

## 五、事件日历：事件日从材料证据来，不手打（`quant_research/event_calendar.py`）

**为什么必须做**：手打 3 个事件日能演示，扩到 ~20 份披露就会开始出错 —— 本轮就出过一次（口算的
洋河事件日 `2025-04-28` 与证据文档的 `2025-04-29` 差一天，t0 整段错一个交易日）。所以事件日**只从
材料自带的证据里取**，判据**不重写**：复用 `adapters.disclosure_ingest._declared_disclosure`
（它按专项 §3.2 把 `?asof=` 这类查询参数排除在外）。

| 纪律 | 落成 |
|---|---|
| 事件日来源 | 来源字段（`disclosure_date`/`declared_disclosed_at`/…）→ 已知格式 URL → 操作者声明；`date_basis` 如实记录，声明日期**不冒充**来源证据 |
| 精度不足不入表 | `date_precision != day` ⇒ 列入 `excluded` 并写原因（无法确定"之后第一个交易日"，不猜） |
| 类别靠规则 | `CATEGORY_RULES` 是数据表，命中关键词即类别并记 `matched`；一条不中记 **`未分类`**，**不硬塞进某一类** |
| 可回溯 | 条目带 `material_id` / `url` / `raw_sha256`；`load_materials()` 读材料目录（`index.json` + 每条 `meta.json`，同一材料只算一次） |

**离线实机验证**（不走网络，只用已准入材料的 `meta.json`，输出
[y2_event_calendar_20261005.json](y2_event_calendar_20261005.json)）：
`ui-05dde104ac` 材料目录 → 1 条事件（`002304` @**2025-04-29**，类别 `定期报告`，
`date_basis=source_url_format`）→ 读数 `reading_hash=6891caa62211…`，
**`input_fingerprint` 与第四节手打事件的那次完全相同**（`3dfabdcac371…`）、t+20 超额 **−5.99%** 一致
—— 即"日历自动取到的披露日"与"人工核对过的披露日"是同一个，可互相印证。

**巨潮公告查询当前取不到数（环境）**：主环境网络策略解析到 **`198.18.0.38`（TUN 代理 fake-IP）**，
`NetworkPolicyError: 解析到非公网地址` ⇒ 12 次查询全部失败、`verified_categories` 为空。
这是**环境状态**（该通道本轮之前实测可用），不是"这家公司没有公告"，所以脚本把失败逐条记为
`errors`、把 0 行标成"该类别码未取到行（不等于没有此类公告）"。**类别码也尚未实测验证** →
扩到全类别公告列表是明确的下一个待办，不是已完成项。
