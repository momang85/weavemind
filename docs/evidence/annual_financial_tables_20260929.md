# 年报 PDF 财务表抽取器（第二家公司事实化的第一步）

- 基线：`61b3b86`。目标材料：京蓝科技（000711.SZ）2020 年年度报告（更正后），
  用户提供巨潮直链，已按正常入口准入（见 `second_company_jinglan_20260929.md`）。
- 新文件 `adapters/annual_financial_tables.py` + `test_annual_financial_tables.py`（11 用例）。
  未调模型、未碰真库；全文离线（真实 PDF 已落在 `%TEMP%\wm_jl\doc.json`）。

## 1. 能吃的形态（都是真实年报里见过的）

| 形态 | 处理 |
|---|---|
| 表头 `2020 年 2019 年 本年比上年增减 2018 年`（**单空格**分隔） | 按年份 token 解析，不假设分隔符 |
| 行内带**百分比列** `-47.65%` | 百分比不当金额（否则 2018 会拿到 -47.65，整列错位） |
| 标签跨行 `归属于上市公司股东的净利润` + `（元）` | 标签与数字可分行；数值可续行取 |
| 千分位 / 负号前置 / **括号负数** `(1,234.56)` / 全角数字 / `—`（=无，**不是 0**） | 统一解析；`—` 视为无值 |
| 单位标注 `单位：元 / 千元 / 万元 / 百万元` | 按标注**显式换算**到元，并记 `unit_source` |
| 日期串 `2019 年 2 月 25 日 至 2020 年 12 月 31 日` | 日期整段跳过（其中的数字不是金额） |
| 跨表同名项 | 按 `TABLE_PRIORITY`（主要会计数据 > 合并报表 > 母公司报表）取一个，并把分歧记进 `cross_table_conflicts` |

## 2. 宁可拒绝（实测会误配，故默认关闭）

| 反例 | 行为 |
|---|---|
| 数字被 PDF 拆行：`1,279,570,42` + `9.23` | `split_number` 拒绝（拼起来是 127,957,042，**看不出来的错数**） |
| 同一张表里同一项两个不同值 | 该 **(指标,期间,表)** 整体不入账（不按先后顺序静默择一） |
| 找不到含两个及以上期间的表头 | `no_periods` 拒绝 |
| 数值个数与表头列数不匹配 | `column_mismatch` 拒绝 |
| **`期末余额/期初余额` 式表头（表头里没有年份）** | `allow_anchor=False`（默认）：**不锚定**。真实报告实测锚定会误配**附注表**——京蓝 2020 应付账款取到 650,625 元，而合并资产负债表是 1,743,811,151.80 元（差 ~2680 倍）。抽错一个数比少一个数危险得多 |

## 4. 仍未完成（下一步的确定入口）

1. **`operating_cost` / `accounts_payable` / `total_liabilities` 还没有**：它们所在报表的表头
   是"期末余额/期初余额"式（无年份），默认关闭锚定后取不到 → 因此
   **`gross_profit` 无法派生** → 利润桥/营运资本/情景在京蓝上仍被正确拒绝。
   下一步：把"报表标题 → 期间"的锚定做**可靠**（例如要求表头到报表标题的行距、或要求同一
   数值在两张表里互相印证后才入账），而不是靠远距离搜索。
2. **`to_dataset` 掉 revenue**：直接调 `extract` 有 12 条（含 revenue 2020/2019），
   但经 `to_dataset` 冻结后只剩 10 条且报"缺失 revenue"。已定位到"抽取输出 → 冻结"这一段，
   未定位根因（下一批第一件事）。
3. 因此**四族模型尚未在京蓝上跑**（目前只有 `cash_quality` 可跑：缺 gross_profit 与占款字段）。

# 更正（2026-09-29 架构纠偏 A0，基线 `7c5fe0c`）

架构主审的离线复验（`docs/evidence/20260929-acquisition-facts-review.md`）证明本文上面的
"12 条 / 8 个真值一致 / freeze 吞收入"叙述**与当前实现不符**。逐条更正如下，旧文保留。

| 本文旧说法 | 更正 |
|---|---|
| "抽取 12 条事实" | 基线 `7c5fe0c` 的 `extract` **只有 10 条**（无 revenue）；12 条是更早一版的行为 |
| "`to_dataset` 冻结后掉 revenue（freeze 吞数）" | **错**。收入从未进入 `extract` 输出：前缀匹配把 `营业收入扣除金额/扣除后金额` 当成了营业收入，与真实收入同表冲突后整项被删。**不是 freeze 的问题，也没有放宽 freeze** |
| "8 个真值与人工从正文读出的数逐位一致" | 那是**执行者机器核查**（同一个抽取器读数与同一份文本比对），**不是独立研究员人工复核**；不得当作独立证据 |
| "2020 应收账款 1,279,570,429.23（合并）" | 更早一版确实取到过，但**同时**把母公司 18,600,000 标成了"合并"；基线版则是母公司数被当合并数。正确行为：拆行无法可靠解析 → **拒绝并给原因**，且母公司/合并**分开** |

## A0 修正后的实测（同一份缓存原件，273 页）

- **不再跨口径补齐**：母公司 18,600,000 现在标 `母公司`（`caliber_source=表名「母公司资产负债表」`）；
  合并 2020 应收账款因**拆行**（`1,279,570,42` + `9.23`）被拒绝，拒绝原因 `split_number`，
  带 PDF 页码；**没有**用母公司数填合并缺口。
- **表性质不再丢**：2020 存货不再取 2020-01-01 会计政策调整表的 680,900,264.45；
  该行以 `table_unrecognized` 拒绝（附注/政策调整/季度摘要一律不取）。
- **收入恢复**：`营业收入(元)` 识别为 revenue（合并、主要会计数据、PDF 第 6 页），
  `营业收入扣除金额/扣除后金额` 不再被当成收入（后缀出现"扣除"即不是该指标）。
- **元数据必须有证据**：单位/币种来自表头单位标注（`unit_source`/`currency_source`），
  口径来自表名（`caliber_source`）；无单位标注 → `no_unit_evidence` 拒绝（不再默认"元"）。
- **身份与定位**：接受的事实带非空 `fact_id`（`facts.make_fact_id`）；定位为
  `PDF 第 N 页 · 表名 · 行「原标签」`（用 `page_offsets` 反查页号，清洗后的行号不再冒充页码）。
- **毛利派生**：只在同主体/同期间/同口径/同币种/同单位且输入带 `fact_id` 时派生，
  携带 `derived_from` + `formula_version=gross_profit_v1`（跨主体/跨币种/缺身份一律不派生）。
- **`营业总成本` 不再映射到 `营业成本`**（语义不同，不能替代）。
