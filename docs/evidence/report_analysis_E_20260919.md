# 批次 E 证据：让研究报告有"经济分析"（报告写全 + 财务图 + 派生比率 + 分析覆盖提示）

起因：产品负责人从**经济学家**角度审 `ui-2084c2c9cc` 的报告与图片，指出"少了东西"。
本批把缺口补到四层：底稿派生比率（数据）、报告内容要求（生成）、财务分析图（图表）、
分析覆盖检查（验收，**只提示**）。

## 1 缺口是什么（审阅结论，均有实机证据）

**报告正文（4324 字）**：只有 2 个财务数字（归母净利 862.28/747.34），且用在"论证口径
归属"的句子里；营业收入、经营活动现金流、同比、毛利率、ROE、资产负债率一个都没写，
没有任何同比/质量/结构/风险/结论段落。连 `report_generator` 系统提示要求的
「关键数据一览」表也没有。

**图片**：`chart_1.png` 标题"市场规模对比（亿元）"，实为 16 个会计科目（营收/净利/毛利润/
经营利润/总资产/总负债/经营现金流/研发投入 × 2 年）塞进同一坐标轴；每个"序列"只有一个点
→ 16 个孤立圆点 + 16 项图例；总资产 2989 亿与研发投入 6.95 亿同轴 → 小项不可见；
流量与存量混比；脚注把原始 API URL 印了出来。`market_data.png` 是同一错误的柱状画法。
另四张是检索统计图，其中 `topic_terms` 的"热词"是接口**英文字段名**（null 5929 / RATIO
1648 / PK 1236），`market_trends` 画的是报告自己声明"未予采用"的 2025 半年报数据。

**根因（机制层，不是模型偷懒）**：① 固定研究路径的 4 步没有图表步骤、也不要求
`[CHART_DATA]`，仓库里唯一写了"营收/净利对比柱状图 + 同比 + 毛利率趋势 + 盈利质量/现金流
健康度"的指令在 `templates.json` 里，被固定路径绕过了；② 图表数据通道只吃
`financials.json` 的 9 个原始指标，**不吃底稿的同比**；③ 规格生成把财务行一律归一成
"市场规模"一张图；④ 渲染层没有分组柱、折线序列键取 `caliber` 导致退化成单点；
⑤ 验收侧没有任何"分析要素覆盖"检查——`number_traceability` 只审已出现的数字
（一个数字都不写反而 pass），`requirement_coverage` 只要"出现过的数字 ≥50% 可溯源"。

## 2 改了什么

### E1 派生比率（底稿层）

`working_paper.build_working_paper` 在同比段之后新增**同年比率**：净利率
（`net_profit/revenue`）、经营现金流对净利润的覆盖（`operating_cashflow/net_profit`）、
资产负债率（`total_liabilities/total_assets`）、研发投入强度（`rd_expense/revenue`）。
只用**同年同口径的已选事实**，带 `formula` + `derived_from` + `unit="%"`。
两条纪律（与同比区分开）：**缺输入不生成、不记问题**（契约可能没要求那个指标）；
**分母为 0 / 输入口径不一致只记审计提示**（`audit` 不参与 `ok` 判定）——不像同比那样
把交付判成不达标。`facts.DERIVED_METRICS` 补中文标签（含 `*_yoy`，此前注入块里是英文 slug）。

实机数据复算（贵州茅台，2023/2024）：净利率 49.64/49.52%、现金流对净利覆盖 89.11/107.23%
（2024 年 >100%，利润有现金支撑）、资产负债率 17.98/19.04%、研发强度 0.41/0.40%。

### E2 报告写全（生成侧）

新增 `_REPORT_ANALYSIS_REQUIREMENTS`（与格式要求并列，在报告/总结步骤注入），给一份
**可检查的骨架**：① 关键数据一览表（指标×期间×同比×口径×来源，覆盖必需指标与派生指标）；
② 逐项同比解读；③ 盈利质量（净利率/毛利率）；④ 现金流质量（覆盖>100% 说明利润有现金
支撑）；⑤ 结构与杠杆（资产负债率）；⑥ 风险与结论；⑦ 缺口纪律。只在**有 [已选事实] 块**
时注入（通用任务没有那块，硬套会要求模型写拿不到的数字）。固定研究路径的报告步骤指令
同步点名这些小节；注入块说明行改为"同比与比率均由系统按已选事实重算…报告须逐个给出"。

### E3 财务分析图（数据 → 规格 → 渲染）

- **数据**：新增 `working_paper_export.chart_rows`（只算不写）——以**底稿**为准
  （含同比与比率），**只保留契约期间**（实机那次越界数据进图的问题就此关闭）；
  并给出可读来源名（"东方财富数据中心（A股）"），不再把接口 URL 印在图上。
- **规格**：新增 `chart_specs.financial_research_specs`（确定性，不经 LLM）：图1 两期核心
  指标对比（分组柱）、图2 同比增速（柱）、图3 盈利与现金流质量两期对比（分组柱）。
  结论由数据算出（如"两期核心指标均上升，经营活动现金流净额增幅最大（38.85%）"），
  不是"随年份变化"式同义反复。
- **渲染**：`chart_assembly.RENDER_CHART_SCRIPT` 新增 `render_grouped_bar`（多序列柱 +
  图例 + 数值标注），`CHART_TYPES` 放行 `grouped_bar`；`series_key` 改为优先取
  `series`/`metric`（此前整串 label 当序列 → 单点退化）。
- **只出财务图**：有落库契约的研究任务不生成检索统计图（`entity_frequency`/
  `source_distribution`/`topic_terms`/`market_trends`），也不走"市场规模"兜底；
  财务图由底稿确定性生成。顺带修 `topic_terms` 把**原始 JSON 快照**当散文分词
  （字段名成了热词）——JSON 不参与热词统计，数值溯源不受影响。

### E4 分析覆盖检查（验收侧，只提示）

新增 `check_analysis_completeness`：读底稿（`build_result`，与硬门槛同源），逐 (指标, 年度)
核对正文是否出现该数值（归一化千分位/空格），核对派生指标读数与风险/结论段落；
**只把契约点名的必需指标算作必须**（总资产/总负债这类支撑事实缺了不报缺口）。
`counted=False` → 缺口进 `checks.analysis_completeness`（含 `analysis_gaps`），
**不进 overall 的 gaps 汇总**，即"先提示、不计入门禁"。
顺带清掉 `check_requirement_coverage` 里那段死循环（`if ... or True: pass`）。
