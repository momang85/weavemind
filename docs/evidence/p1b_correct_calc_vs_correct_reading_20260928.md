# P1-b：正确计算 ≠ 正确解释 —— 归因方向与底稿符号相反（2026-09-28）

依据：`docs/DSH真实样本复核与下一批执行_20260928.md` P1 第 ② 项「"正确计算不等于正确解释"
（`report_brief.py:951` cur→prev 导致采用稿"毛利209亿→247亿"实为 2024→2023 未标年份；
"利润侵蚀主要发生在毛利线以下"不得用利润率差替代金额科目归因）」。
冻结样本 `ui-a06a005c9b`（洋河股份 2023–2024）。基线 `375479e`。
**未跑付费整链**；下列全部由冻结样本磁盘产物离线复算。

## 一、`report_brief.py:951`：三处毛病，同一行

采用稿 `reports/report.md:44` 原文：

```
材料：**分解覆盖（部分）**：毛利额（按销售模式分组合计）：20920103385→24728464886；
期间费用合计：6934875260→6681605162（来源 [2]；第 11 页 · 小节：…（字符 7532-7601））
```

| 毛病 | 后果 |
|---|---|
| **无单位** | `20920103385` 是元还是万元？读者无从判断 |
| 箭头是 `本期→上期`（**时间倒序**） | 读起来像"从 209 涨到 247"，把 **−38.08 亿元的下降**读成了增长 |
| 同上 | 期间费用 `6934875260→6681605162` 时间上其实是**上升 +2.53 亿元** |

**修法**：新增 `_amount_text()` 与 `_derived_pair_text()`
（`report_brief.py`，`_metric_direction` 上方）：

```
毛利额（按销售模式分组合计）：2023 年 247.28 亿元 → 2024 年 209.20 亿元（-38.08 亿元）
期间费用合计：2023 年 66.82 亿元 → 2024 年 69.35 亿元（+2.53 亿元）
```

- 年份取自**材料自己声明的报告期**——为此给 `extract_profit_decomposition` 的返回
  补了 `periods` 字段（此前报告期只写在 `boundary` 文案里，正文渲染时无从可靠解析）；
  取不到年份时退成"上期/本期"，**不猜**年份，方向仍然明确；
- 单位随行（元 → 亿元两位小数，与全文记账口径一致），并给出**带符号**的变化量；
- 单值派生行（如"省外与省内收入降幅差"，它本身就是两地之差、不是两期配对）如实写单值，
  不硬凑成"两期"、也不把一个已取得的读数说成"未取得"。

## 二、归因倒置：底稿里有机械反例，却只判"部分支持"

采用稿结论段原句（实读 `reports/report.md:193`）：

> …盈利质量指标（归母净利率 −7.13 个百分点、毛利率 −2.09 个百分点）同步走弱，
> **利润侵蚀主要发生在毛利线以下**；…

这是**用利润率差替代金额科目归因**。按金额：

| 量 | 值 |
|---|---|
| 毛利润变化 | **−38.01 亿元** |
| 归母净利润变化 | **−33.43 亿元** |
| 毛利线以下净额变化（Δ归母净利 − Δ毛利） | **+4.58 亿元（净缓冲）** |

毛利率降幅（2.09pp）小于净利率降幅（7.13pp）**不等于**毛利线以下在金额上拖累更多——
收入同时在缩，百分比差不能替代金额科目归因。侵蚀发生在**毛利线上**，句子说反了。

而这个符号**底稿里就有**（`working_paper.json.derived` 的
`net_profit_gross_gap_change`，带 `formula="(66.73 - 100.16) - (211.25 - 249.26)"`
与 4 个输入 `fact_id`），此前没有任何检查读它。

**修后 vs 修前（同一句、同一批底稿事实，离线复算）**：

| | 状态 | 理由 |
|---|---|---|
| 修前 | `partially_supported` | 数字部分对上（`net_margin`/`gross_margin` supported），句子的**中心倒置不可见** |
| 修后 | **`unsupported`** | 「归因方向与底稿相反：底稿「毛利线以下净额变化」为 +4.58 亿元（毛利线以下是**净缓冲**，不是主要拖累）…**金额归因不能用利润率差替代**…」 |

**注意（不夸大）**：该句修前**不是** `bound`——句中有几条断言因指标/期间语义未绑定而
落 `needs_check`，所以整体是 `partially_supported`。本批把"说不出问题"变成
"**点明**问题"，方向正确，但不是"从通过改成不通过"。

## 三、修法：只做**机械符号核对**，不替读者判断归因

新增 `_gross_line_attributions()` / `_gross_line_conflict()`，在 `_claims()` 里对
**本来要判 bound / partially_supported 的主张**加一道闸门：

- 按**子句**判定（同一子句里既有毛利线某一侧、又有归因/变化措辞才算归因句）——
  "毛利端与期间费用取自发行人毛利率表（各自有定位）"这类**口径/来源说明**不会被误判；
- **否定式翻面**："利润下滑**并非**主要来自毛利端" = 归因在**毛利线以下**
  （冻结样本 `d1_night_failure_samples_20260921.json` 里就是这种写法）；
  裸"非"不参与翻面（否则命中"非经常性损益"）；
- **逐子句**都看：一句里前半句一致、后半句矛盾时仍要抓到矛盾；
- 底稿**没有**这个事实时不表态（不猜）；`gap == 0` 不表态。

## 四、行为口径变化（必须明说）

- **没有**改任何阈值、门禁参数或豁免清单；`_TRACEABILITY_THRESHOLDS` 等一律未动。
- **但是**：一句归因倒置的结论现在会进 `unsupported`（原来可能是
  `partially_supported`），因此**可能**让某份交付从"就绪"变"草稿"。
  这正是本项的目的（"不得用利润率差替代金额科目归因"），但它确实是一处
  **判定收紧**，不是纯重构——架构师与用户需要知道这一点。
