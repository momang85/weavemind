# Y2 证据：独立交易日历 —— 把"停牌"与"休市"分开（2026-10-05）

> **边界**：0 元 API、一次免费抓取、未联网（后续读取全离线）、未调模型、未改权限/预算。
> 日历来源为新浪（akshare `tool_trade_date_hist_sina`），**无正式许可** ⇒ 标 `免费源·仅内部试验`，
> 不得进对外下载包。日历**不含停牌信息**（停牌是标的级事实）。

## 一、为什么必须有它（缺它会算错什么）

"某标的当天没有行情行"有两种完全不同的解释：

| 情形 | 真相 | 不修日历的后果 |
|---|---|---|
| **休市** | 全市场都没交易 | 只是没有那天 |
| **停牌** | 市场开着，这只票不能交易 | `t+5` 这类"第 N 个交易日"**静默错位**；`backtest` 的"当月第一个交易日"错位 ⇒ **该月再平衡被静默跳过、不留任何痕迹** |

本轮补之前，只能拿**基准序列当日历代理**报"疑似"（`suspension_suspect`）——那是**降级方案**，
分不清停牌与休市，也没有覆盖区间的概念。

## 二、落地

1. **抓取侧** `scripts/fetch_trading_calendar.py`（数据环境）：新浪日历 → CSV + 侧车
   （来源/许可/范围）。实测 **8797 个交易日，1990-12-19 → 2026-12-31**，一次调用取全。
2. **读侧** `adapters/trading_calendar.py`（**只用标准库**）：`import_file`（`dataset_id = sha256(文件字节)`）、
   `load`、`is_session`/`next_session`/`prev_session`/`session_at_offset`/`sessions_between`、
   `suspend_dates`。落地目录 `WEAVEMIND_CALENDAR_DIR` → 否则 `<工作区根>/../trading_calendar`。
3. **接入（可选参数，不传行为完全不变）**：
   - `event_returns.compute(..., calendar=)`：`t±N` 按**日历**定位；标的当日无行情且有日历覆盖时
     记 `missing` 并写明"**交易日历确认 X 是交易日**…不是休市"；`suspension_dates` 是**确证**清单，
     `suspension_certain` 标出是结论还是疑似。
   - `backtest.run(..., calendar=)`：交易日取日历（行情覆盖区间内），停牌日的再平衡**留下拒绝记录**
     而不是静默跳过。

## 三、纪律：**覆盖区间外一律 `unknown`**

`is_session` 在日期超出日历覆盖时返回 **`None`**，不是 `False`。这条是防"把日历太旧说成那天不开市"。
同理 `suspend_dates` 在区间超出覆盖时 `ok=False` 并写原因，**不下停牌结论**。
偏移超出日历覆盖时，事件算子把该点记为 **`pending`**（未成熟）而不是 `missing`——
`missing` 会暗示停牌，而那时我们并不知道那天开不开。

## 四、实机验证

| 验证 | 结果 |
|---|---|
| `2025-09-05`（京蓝更正版披露日） | `is_session=True` ⇒ 当日**京蓝停牌**是**确证**，不是疑似（此前只能报"疑似"） |
| `2025-10-01`（国庆） | `is_session=False` ⇒ 休市 |
| `2030-01-01` | `is_session=None` ⇒ 覆盖外，**不判休市** |
| 两家公司三个已核对事件 | 指标**一个没变**（洋河 t+20 −6.92%／−5.99%、三一 −4.19%），因为这两只在窗口内无停牌 ⇒ "加日历"没有偷偷改写旧结论 |
| 京蓝手算小样 | `gold_diffs=[]`（手算仍逐点一致），并新增 `suspension_dates` 确证字段 |
| 回测（002304＋600031） | 66 笔成交／24 条拒绝不变、`audit_ok=true` |

**跨口径一致性**由测试锁住：`test_same_numbers_with_and_without_calendar_when_no_suspension`
（无停牌时两种口径必须同数字）。

## 五、本轮被测试抓出的两个真缺陷（都是我的）

1. **`trading_calendar.ok()` 返回的不是 `bool`**：`bool(p) and (src != "unavailable") and p["sessions"]`
   —— Python 的 `and` 返回**最后一个操作数**，于是它返回了整份 `sessions` 列表（8000+ 个日期）。
   布尔上下文里行为正确，但它被写进读数与证据 JSON，**文件从 14KB 涨到 60KB+**。
   已改为 `return bool(...)`，并加注释说明这个坑。
2. **非观察点的 `date` 被硬编码成 `None`**：日历明明算出了"该点是 2025-09-09"，输出组装却把它丢了，
   于是"停牌发生在哪一天"又没了。已改为透传 `p.get("date")`。
   —— 这是测试逼出来的：我原本的测试期望也是错的（见下）。

**顺带纠正我自己的一个测试误判**：我先前以为"披露日当天停牌 ⇒ t0 落在披露日、状态 missing"。
实际算子沿用**已确立的约定**：`t0 = 截点之后第一个交易日`、截点当日只作价格起点——
所以京蓝的 `anchor=2025-09-04`、`t0=2025-09-08`，09-05 出现在 `suspension_dates` 里。
是**测试写错**，不是算子错。
