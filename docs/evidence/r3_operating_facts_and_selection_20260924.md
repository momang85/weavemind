## 3. 选择机制：有据覆盖优先于观察句数

`report_quality.candidate_quality` 新增：`answered_questions` / `partial_questions` /
`unanswered_questions`（分母来自**契约**、由材料侧评估决定，删正文不缩小分母）、
`contradictions`（跨章节同指标同单位不同值的次数）、`facts_missing`（底稿必需事实/派生
读数缺项）。`_quality_tiebreak` 顺序改为：

**有分析 → 有据覆盖更多 → 跨章节矛盾更少 → 信息保留更全 → 未支持结论更少 → 重复更少 →
观察更多（有上限）**；长度始终不参与。

固定反例（用例锁定）：候选多写 8 句观察但契约覆盖不增 → **不得胜出**；
候选少写观察但多答一个契约问题 → 胜出（`TestQualityVectorOrder`）。

## 4. 缓存身份：读到旧缓存必须标陈旧或重建

`narrative_evidence.build` 记录 `snapshot_sha256`（按当时 `fetch_snapshot.json` 字节）；
`report_brief._evidence` 读侧比对当前资料：不符（或旧格式没有该字段）即按当前资料**重建**，
并记日志。用例：`TestEvidenceCacheIdentity.test_stale_cache_is_rebuilt_on_material_change`
（追加一段披露 → 缓存指纹变化、定位数不降）。
