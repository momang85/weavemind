# 织光 WeaveMind 长期目标与执行计划

> 版本：2026-10-19 ｜ 架构师制定 ｜ 依据：README 路线图 + 竞品调研（21产品）+ Phase 1-4 真机验证 + E2E 验收缺口

## 一、长期目标

如果织光大获成功，它应该成为：**财务研究领域的"可重复性标准"——让每一个研究判断都像可复现的实验，而不是一次性的意见**。

### 三层愿景

| 层级 | 定位 | 衡量标准 |
|------|------|----------|
| **个体研究员** | 让一个人做到以前需要3人团队才能做的研究质量 | 研究结论经得起追问 |
| **银行对公客户研究** | 企业信用研究的方法论基础设施 | 行业级别的研究标准 |
| **可验证研究标准** | 定义"什么叫做一份可信任的财务研究" | 可量化的研究质量维度被广泛采用 |

### 核心命题

现有金融研究的根本问题：**结论和数字之间的链条是模糊的**。分析师写"营收增长由产品结构改善驱动"，但没有人能快速验算这句话背后的数字是否成立、假设是否合理、来源是否可追溯。

织光的定位：把研究判断变成可计算、可追溯、可持续检验的结构化产物。不是加速写报告，而是改变什么叫做"一份合格的研究"。

### 织光不应该成为什么

- **不是自动化决策系统**：不输出"买/卖/持有"，不替用户做判断。"机器验收+研究状态+人工复核独立展示"、"未验收草稿"标签必须一直保持
- **不是数据库产品**：不去和 Wind/东财竞争数据覆盖广度。数据是输入，织光的价值是研究方法论和研究流程
- **不是通用 AI 助手**：做窄做深，在上市公司经营研究这个垂直领域做到不可替代

### 关键洞察

织光的智能增长点在确定性层，不在AI层。更多LLM调用不会让研究更好。让研究更好的是：
1. 把研究判断变成可跟踪的结构化对象（claim有证据指针、置信度、被加强/削弱的记录）
2. 让确定性分析可组合、可比较（A公司的现金转化为什么比B好——分解到收入结构/成本/营运资本/税项）
3. 让编排理解失败并自适应（不是重试同样的方法，而是换路径）
4. 让研究能随时间更新（新披露来了，自动检查哪些旧判断受影响）

一句话：**从"生成一份报告"升级到"维护一个可检验的研究状态"**。

## 二、当前状态（2026-10-19）

### 已验证可行的

- 16进程栈稳定运行，监督重启真机验证通过（Phase 4 task 21）
- 确定性分析核心（利润桥、现金桥、情景/反向阈值）计算正确，数字可回查到底稿
- 诚实性框架有效——报告自陈缺口、未验收草稿标签、不替用户标记通过
- 版本化交付链工作——正文/图表/底稿/来源按版本打包，哈希校验
- LLM熔断、Redis降级、死链缓存等韧性机制在真机上有证据（Phase 3-4）
- 报告主文长度控制 + body/appendix拆分（Phase 4 task 22）

### 还不够好的

**1. 编排智能不足**（影响最大）
- 成功率 54.8%，虽然93%的"失败"是编排会计问题而非worker失败，但对用户来说任务就是没完成
- web_search 27%误派发到错误worker，返回0链接Markdown却记为SUCCESS
- 步骤间没有依赖感知——gate步骤的前置条件没满足就dispatch，然后失败，然后级联阻断下游
- 任务崩溃后全量重跑，1133秒的工作可能因为一个进程退出全丢

**2. 研究深度不够**（影响其次）
- 目前是单次研究：plan→execute→report→done，没有迭代
- 研究续页有离线样品，但不是live任务流程
- 单公司分析，没有结构性多公司比较
- 报告质量靠验收器事后抓问题，不是生成端预防

**3. 工程成熟度不够**（影响最小但拖累开发）
- orchestrator_v2.py 8445行、web_ui.py 6522行，改动风险高
- 79个测试文件平铺根目录
- 报告缺免责声明等合规要素（Phase 5正在修）

## 三、执行计划

### 总览

```
Phase 5 (信任底线) ──→ Phase 6 (编排智能) ──→ Phase 7 (研究智能)
                                              │
                                    ┌─────────┴──────────┐
                                    ▼                      ▼
                          Phase 8 (比较)            Phase 9 (事件/风险)
                                    └─────────┬──────────┘
                                              ▼
                                     Phase 10 (机构化)
```

Phase 5→6是硬顺序：先让产出可信，再让产出可靠完成。
Phase 7是价值跃迁点——做完这一步，织光从"报告生成器"变成"研究状态管理器"。
Phase 8/9可以并行推进。Phase 10是最后的工程化。

### Phase 6 — 编排智能（成功率 54.8% → 85%）

**目标**：当前最大的杠杆。成功率上不去，后面所有功能都建在沙子上。

**核心改动**：

1. **自适应路由**
   - routing metrics（task 16/17已采集）从被动观察变成主动纠正
   - content_summarizer反复接到web_search任务且返回0链接时，自动修正CAPABILITY_WORKER_MAP
   - 误派发检测：步骤声称success但返回0链接/0数据 → 标记为实质失败 → 触发重派发

2. **DAG步骤依赖**
   - 把线性步骤列表升级为有向图
   - gate步骤的前置条件未满足时等待而不是dispatch后失败
   - 级联阻断改为级联等待——前置完成后自动解锁

3. **失败分类与决策**
   - 步骤失败后分类：数据缺失/网络/模型/逻辑
   - 分别决定：重试/换路径/跳过/重规划
   - 不是一刀切retry（当前RETRY_POLICY只对网络错误有效）

4. **断点续跑增强**
   - Phase 5 task 26打底（跳过SUCCESS步骤）
   - 在此基础上加"续跑时只重做失败步骤的后继链"
   - 失败步骤本身按分类决策处理，不是简单重跑

**预期**：
- success_rate_dispatched 从~65%提到>85%
- 用户感知的"任务没完成"大幅减少
- gate_blocked和cascade_blocked占比从~40%降到<15%

**设计文档**：Phase 5验收后开始写，预计4-6个task。

### Phase 7 — 研究智能（从一次性到持续性）

**目标**：价值跃迁点。织光从"报告生成器"变成"研究状态管理器"。

**核心概念：Claim是第一类对象**

当前研究结论活在报告文本里，读完就散了。提取成结构化的claim：

```
claim: "伊利2024年经营现金流覆盖率257%，当期利润有现金支撑"
evidence: [底稿cash_flow_coverage_cell, 年报P32]
confidence: high
status: strengthened | weakened | unknown | refuted
last_checked: 2024年报
```

**能力构建**：

1. **续页变live**
   - 用户提交新期数据，系统自动检查每个claim的状态变化
   - 生成续页——不是人重写，是系统增量更新
   - 现有离线样品（洋河2025H1续页）变成live任务流程

2. **最弱环节提示**
   - 报告生成后，系统标注置信度最低的claim
   - 建议下一步研究什么
   - 验收器的gaps变成可操作的研究队列

3. **研究队列**
   - 被新数据削弱的claim自动生成后续研究任务
   - 研究不再是一次性，而是持续维护的活状态

**预期**：
- 研究从"读一份报告"变成"维护一个活的判断状态"
- 每次新披露都能增量更新，不需要从零开始
- 这是定义性的变化——做完这步，织光的定位从工具变成基础设施

**设计文档**：Phase 6验收后开始写，预计6-8个task。

### Phase 8 — 比较智能（从单公司到多公司）

**目标**：Phase 7解决了时间轴上的跟踪，Phase 8解决横截面上的比较。

**核心改动**：

1. **实体注册表**
   - 公司作为第一类对象，带行业/规模/报告期属性
   - 支持公司间关系（母子公司、同行、上下游）

2. **结构性比较引擎**
   - 不只并列A和B的数字，而是分解差异来源
   - 示例："A的现金转化率比B高15%，其中收入结构贡献+8%，营运资本管理贡献+12%，税项拖累-5%"
   - 复用现有利润桥/现金桥，扩展为跨实体比较

3. **同行自动选择**
   - 按行业/规模/商业模式自动选可比公司
   - 不需要用户手动指定

4. **行业模式识别**
   - 分析N家同行业公司后，识别共性模式和异常值
   - 异常值自动标记为"值得追问"

**预期**：研究者能做"为什么这家比同行好/差"这种结构性问题，不只是单公司描述。

---

### Phase 9 — 事件与风险智能

**目标**：把研究连到现实世界。

1. **事件驱动**
   - 公司公告/新闻触发自动研究——检查受影响的claim
   - 不是全量重跑，是增量检查

2. **事件研究**
   - 披露日→1/5/20交易日市场反应→与经营判断并列
   - 已有离线样品（2026-04-28年报+三窗口市场对照），需要live化
   - 免费源行情默认仅内部试验，不随交付包外发

3. **企业风险卡**
   - 财务信号+现金流信号+事件信号→结构化风险评估
   - 不是信用评分，是研究线索
   - 信用评分/违约概率/交易反欺诈须有授权数据/标签，当前不推进

---

### Phase 10 — 机构化

**目标**：团队复核、机构隔离、身份集成、审计合规。这是文档里说的银行部署方向。

- 团队复核工作流（多人协作标注、审核、版本管理）
- 机构隔离（多租户、数据隔离）
- 身份集成（SSO、权限矩阵）
- 审计合规（操作日志、数据血缘、合规报告）
- 运维验证（SLO、监控、灾备）

**前提**：必须建立在前面所有阶段可靠的基础上。

## 四、优先级决策原则

1. **产出可信优先于功能丰富**：Phase 5→6是硬顺序，先让现有产出可信再扩展
2. **确定性层优先于AI层**：智能增长点在确定性分析可组合/可比较/可跟踪，不在更多LLM调用
3. **研究方法论优先于数据覆盖**：不去和 Wind/东财竞争数据广度，在研究深度上做不可替代
4. **诚实性优先于完成度**：宁可标"未验收草稿"也不替用户标记通过
5. **垂直深度优先于水平广度**：在上市公司经营研究做到不可替代，不做通用AI助手
