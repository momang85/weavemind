## 一、行业共识（跨 21 个产品收敛出的三条主线）

1. **溯源是研报类产品的生命线**：报告型产品（OpenAI/Gemini Deep Research、NotebookLM、Kimi、秘塔、
   Anthropic 研报系统）全部收敛为"句内/句末编号引用 + 文末来源清单"格式；FactSet/AlphaSense 做到
   段落级原文定位；社区最大痛点是**引用链接失效**与**来源被注入污染**（有专门清理脚本）、幻觉编造来源
   （Reddit"病态撒谎者"、gemini-cli issue #13672）。
2. **多 agent 成本放大 5–15 倍是横跨所有框架的普遍痛点**（CrewAI quadratic context、Anthropic 15x、
   Claude Code 一次触发 199 agents 烧 5000 万 token）→ 需要 checkpointer（断点续跑）+ 成本拦截对冲。
3. **人机协作最佳实践 = 分级人工确认 + 关键节点中断**（Claude Code permission-mode、Operator 敏感操作
   确认、AutoGen human_input_mode、LangGraph interrupt()、扣子"对齐"确认）；报告类产品把澄清问题前置
   （Deep Research 开始前提问）。

## 二、金融合规红线（监管案例，直接影响本项目定位）

- 方正证券"旧闻当新政"被当作 AI 投研合规警钟 → **数据时效性是硬指标**；

- 历史上券商因"**资料来源标注不明确**"被证监局监管措施 → **来源标注 = 合规底线**。

## 四、下一步优化路线（V1.2，按优先级）

### 🔴 高优先级（可信度与合规底线）
1. **三级溯源链 + URL 存活校验**：报告"论断 → 编号引用 → 文末来源清单"；
   分享/交付前对引用 URL 做存活检查，失效来源降级标注（社区已验证链接失效是最大痛点）。
2. **报告头部数据时效区块**：固定"数据截止时间 / 行情快照时间 / 盘中-盘后-日终 / 延迟等级"，
   排行类任务自动标注数据时间戳（方正旧闻案的直接对策）。
3. **免责声明 + AI 标识模板**：固定"不构成投资建议 + 数据来源与局限 + AI 生成标识 + 引用准确性免责"，
   验收器增加"旧闻/过期识别"检查（监管红线）。

### 🟡 中优先级（体验与差异化）
4. **checkpointer 断点续跑**：任务状态持久化（Redis/SQLite），进程重启后从最后完成步骤续跑
   （LangGraph checkpointer 模式；对冲多 agent 成本）。
5. **关键节点 HITL 中断**：提纲/图表数据/终稿三级人工确认点（对标 Anthropic permission-mode +
   Deep Research 前置澄清）。
6. **数据源开关与透明性**：报告注明"行情/财报来自哪一源、更新频次、是否官方接口"，
   用户可勾选数据源（对标 AlphaSense Search Library）。
7. **工作流可视化看板**：拆解树 / worker 进度 / 中间产物 / 引用链（对标 Bloomberg ASKB 透明 agentic 工作流）。
8. **排行任务"表格 + 口径说明 + 配图"三件套**：样本范围、时间窗口、计算口径、分位阈值
   + 分位柱状图（问财式结构化呈现）。

### 🟢 低优先级（长期演进）
9. 电话会/路演纪要解析（Wind 3C / FactSet earnings call / AlphaSense 专家纪要）。
10. 图表来源与时间水印（东财资金流向图风格）。
11. 开放 MCP/API（IFIND MCP / 券商 Skills 趋势，mcp_lite 已具备基础）。
12. 历史报告库 + 检索增强（东财研报中心模式）。
