# 正门触发条件：普通任务如何走到经营研究交付（2026-10-02）

本文回答一个具体问题：**用普通任务入口（表单 + 直链）提交，什么条件下才会跑出
`analysis/`（分析卡／注册模型／三图／成篇正文）与 17 页同版交付？** 依据是 10-02 三个
真实任务（`ui-17947f055b`、`ui-f6a0ad5f4e`、`ui-14f63dd6ee`、`ui-c066b12a5d`）与代码路径。

## 1. 两个必要条件（缺一不可）

| 条件 | 判据（代码） | 不满足会怎样 |
|---|---|---|
| **A. 研究契约落库** | `working_paper_export.resolve_request` 的 `source == "stored"` 且 `facts.research_shaped(request)`：主体（公司/代码）、**≥2 个期间**、已声明报表口径、`as_of` | 走通用规划器（搜索→摘要→报告）→ **不派发 `3a` data_analyzer** → 没有 `analysis/`，报告是模型自己写的文本（`ui-c066b12a5d`：2351 字符、可溯源 0%） |
| **B. 至少一份可用材料** | 已准入官方原文（检索/抓取或**显式直链**，X0-④ 会直接派发该直链）或结构化载荷 `project/financials.json` | `3a` 会跑，但只能按现有事实建底稿；缺的指标如实进缺口，模型"缺输入/不适用" |

满足 A 时命中**固定研究步骤序列**（`OrchestratorV2._fixed_research_plan` → `_research_steps`）：

```
1  web_search    按契约（公司+期间+年报）检索权威来源
2  web_fetch     抓年报正文页（用户显式直链优先；检索为空也照样抓用户给的地址）
2b web_fetch     （optional）附注/风险页；取不到只记缺口
3  content_summary  只解释[已选事实]
3a data_analyzer    ★冻结数据集→适用模型→分析卡（零模型调用）
4  report_generator 成稿（消费同一份 analysis/analysis_runs.json）
5  package          同版打包
```

`3a` 就是"经营研究组合"的入口：它落 `analysis/{dataset,plan,context,runs,selection}.json`，
`report_brief` 随后把三项主判断／分析摘要／成篇正文／七段式明细／三图装配进正文与 PDF。

## 2. 表单怎么填（正门用法）

在「研究一家公司」表单里给全：

- 主体：**洋河股份 002304.SZ**（公司名 + 代码都要）
- 市场：A 股；期间：**2023 / 2024**（≥2 期）；口径：**合并**；资料截止：2025-04-30
- 目标文本框里附**官方直链**（推荐做法，见 §4）：
  `http://static.cninfo.com.cn/finalpage/2025-04-29/1223370519.PDF`

**只贴直链、不填表单字段 → 不满足 A**，只会得到一份文字报告（`ui-c066b12a5d` 的教训）。

## 3. 怎么一眼看出走没走到正门

工作区（`…/tasks/projects/default/<task_id>/`）：

- 正门：`analysis/` 目录存在（含 `analysis_runs.json`、`dataset.json`、`analysis_detail.md`），
  `reports/report.md` 里有 `## 三项主判断（先看这里）`／`## 分析摘要`／`## 经营驱动分析正文`，
  `reports/report.pdf` 十几页、前两页是主判断，交付包含 `analysis/*.md`。
- 通用路径：**没有 `analysis/`**，`reports/report.md` 是模型文本（常见 2–3 KB、可溯源率低）。

## 4. 显式直链是官方材料准入的推荐用法（已验证）

- 派发侧把用户给的直链作为**选定 URL** 前置进抓取指令；worker 只认这个显式值，
  并在第一个中日韩字符处截断（避免「…PDF；本次…」把中文编进路径）。
- 检索为空、或返回一堆无关来源（东亚银行/官网/电商）都不影响该直链被抓；
  **HTTP 非 2xx 如实判缺口**（不再包装成 success），同一死链不重复抓。
- 注意：直链**只解决材料**（条件 B），不替代契约（条件 A）。要 `3a` 跑起来，两者都要有。

## 5. 与脚本链的关系（不是两条路）

`scripts/v0_yanghe_normal_task.py` 调的是**同一批生产函数**：
`facts.facts_from_annual_tables → build_working_paper → DataAnalyzerWorker._run_financial →
OrchestratorV2._analysis_chart_specs + 渲染 → report_brief → delivery_pipeline.assemble_and_verify
→ web_ui._task_pdf_bytes`。它**跳过的只有**「登录会话 → POST /api/tasks → 步骤派发 / worker 回包」
这一层，因此是**证据**而不是旁路：正门只要满足 §1 的 A+B，走的就是同一条装配链。

## 6. 给架构师的最小验收清单（普通洋河任务）

1. 提交后看页面计划：应含 `3a`（data_analyzer）与 `5`（package）；
2. 分析工作台菜单出现 **经营驱动／现金调节／条件情景**；情景摘要显示 **基准 66.73 亿／默认 80.32 亿**
   左右（采用精确披露后允许合理舍入差，正文会写明）；
3. 复算 A（收入 +10%／毛利率 +1pp）→ 新 run 直接进菜单可选、**不自动采纳**；
   显式采纳后正文/PDF/包同版（`analysis/*.md` 在包内）；
4. 再看一次采纳 B（收入 −5%／毛利率 −1pp）→ 另成一版；两版各自导出；
5. 缺口与人工复核照实：机器 pass ≠ 研究通过，人工复核不由程序代打。
