## 1. 用户目标与当前基线

用户要求：优先保障用户可以流畅使用到 90 分的系统功能。当前只做已有上市公司经营研究功能的可用性闭环，不把扩大功能范围当成进度。

源码基线 `19054dd`。DSH 最新交付声明 Phase 5 已实现死链标注、免责声明与断点续跑，但明确记录“恢复只有 API、没有前端按钮；运行服务尚未加载新代码”。这是待核实的交付记录，不推断当前服务一定仍是旧版。任务列表还显示旧任务进行中，与交付声明不一致，应先核实并更新本会话任务账，不重复实现任务 24–26。

90 分是本批验收目标，不是当前成绩。测试通过、HTTP 200、任务 SUCCESS、机器验收通过均不能单独代表 90 分；最终用户满意度仍待真人反馈。

## 2. 本批范围与执行顺序

### U90-A：核实基线，找出最妨碍使用的阻断点

1. 核对工作区、提交、前端构建、服务加载身份及在飞任务，保护所有已有修改、历史任务与交付包。
2. 优先沿真实网页检查“进入工作台 → 选择公司/期间 → 提交 → 查看进度 → 查看分析/来源 → 修改或补材料 → 导出 → 重开”。逐项记录可用、阻断、未验，不先开展全仓审计。
3. 如果确需加载新代码，先确认没有在飞任务；只通过项目正常启动入口操作，不杀其他服务实例、不清 Redis/数据库。已有任务在运行则先做不需重启的实现。
4. 输出简短阻断清单，按影响用户主流程的程度排序，直接继续 U90-B/C；不是只交一份诊断报告。

### U90-B：用户能操作、能看懂、能从失败继续

1. 为现有恢复 API 补任务页/历史页的可见入口：后端先核实际可恢复条件，再向当前有权限用户展示。运行中、已完成或不可恢复任务不提供误导按钮；不另建恢复服务或状态机。
2. 点击后立即有反馈和防重复提交；接口失败/断线给出明确原因和下一操作，不静默、不无限转圈。取消与恢复语义分开，不扩大现有权限。
3. 核查已有断点续跑：仅当计划/契约/输入身份及所需产物仍有效时复用结果，不只凭 step_id 与 SUCCESS 跳过。修复当前恢复链路所需的最小问题，不重写整个编排器。
4. 状态来自后端真实任务：刷新、离开再回来仍可查看；失败和有缺口的完成能看懂，分别指向重试、补材料、继续或查看草稿。不要用假进度或降低检查门槛制造成功。

### U90-C：现有核心分析真正到达普通用户

1. 沿普通研究入口，把已存在的事实、Dataset、ModelRun、分析卡与报告/图表接通。对完整材料，用户能查看“利润由何而来、现金为何变化、什么条件改变判断”。不要另造分析引擎、数据库或硬编码公司结论。
2. 对本应支持的经营研究任务，调查并修复“有报告/底稿却没有可复算分析输入”的最小根因。非分析任务或材料不全仍如实不适用/待补证，不强行构造空数据集。
3. 用户至少能改一个已有情景参数或补一份合法材料，明确查看候选、采纳与重新验收；图、正文、底稿和导出必须指向所选版本，不能混用新旧结果。
4. 先呈现关键结论、主要贡献与下一观察，技术 ID 和长表放详情。关键数字可回查原件位置；会计贡献、发行人说法、业务假说与未证实原因不得混同。

### U90-D：最少实机复验，交付可审查证据

1. 三个必要场景：完整材料的洋河经营研究；复用同一路径的三一现金研究；材料不足后提示缺口并补材料继续。优先已缓存的官方材料和既有计算，历史样品回放须标明，不冒充新的实时取数。
2. 必须实际通过浏览器操作提交/查看/改参或补材料/采纳/下载/刷新重开。脚本与 HTTP 探针只作辅助，不能代称按钮已验；浏览器不可用时明确该项未验。
3. 在隔离测试环境演练一次中断与恢复，核实未重复执行有效的已完成步骤、未重复扣费/出包。不得为演练故障杀真实在飞任务或用户正在使用的共享服务。
4. 抽查实际下载 MD/PDF/ZIP 的版本身份及成员字节/哈希；检查正文、图表、底稿和来源同版，草稿及限制随包可见。PDF 须打开确认可读，不能仅验 MIME/200。
5. 只跑本批受影响测试文件；有前端修改则做现有 TypeScript 检查与构建并同步既定 dist。不得全仓反复跑测或为了“全绿”修改无关测试。
6. 保持现有预算上限，先缓存/离线确定性验证，不改变模型/供应商/密钥，不采购数据、不新增订阅。真实模型任务只在已有明确授权与剩余预算内执行，避免重复付费整跑；否则如实标实时路径待验。

## 3. 100 分评分表

这是本批工程验收量表，不是预测准确率、投资收益或真人满意度。每个子项 5 分；只有具备可复核证据才记 5 分，失败记 0，未验记 0 并单列。每项证据注明环境、任务/版本身份、实际操作和结果，不以单一样品推及所有公司。

| 维度 | 四个检查项（每项 5 分） | 满分 |
|---|---|---:|
| 进入与操作 | 正常进入；公司/期间/口径明确；提交即时反馈且防重；刷新/重开保留任务定位 | 20 |
| 过程与状态 | 实际进度可见；断线/重连有提示；失败原因可读；缺口有明确下一操作 | 20 |
| 核心研究 | 利润/现金/情景真实可用；关键数字回查；一次改参/补材料形成有效新结果；完整/不足材料按实际区分 | 20 |
| 失败恢复 | 网页恢复入口可操作；权限/状态限制正确；有效断点可复用且过期产物不误用；恢复无重复执行副作用 | 20 |
| 交付与可信度 | MD/PDF/ZIP实际可读可下；所选版本同源；AI声明/死链/缺口可见；机器/研究/人工三态独立 | 20 |

目标：至少 90/100，且以下硬门槛全部通过；未满足则报告实际分数和阻断项，不自行宣称“系统已达90分”。

硬门槛：无已发现的关键数字/主体/期间/口径错配；无新旧版本混包；无越权或密钥泄漏；无代理代签人工复核；主路径无阻断；必需的真实界面操作与恢复复验不能以探针替代。保留所有既有准入、安全、来源许可和隔离门槛。
