# 任务时间轴规范（2026-09-07）

> 防止"同类 bug"回归的单一事实来源：任何与任务生命周期相关的超时/过期常量，
> 必须满足本文件的不等式链；改动常量时先核对本表。

## 一、时间轴常量归属（当前值）

| 常量 | 归属 | 默认值 | 可调入口 | 治理内容 |
|---|---|---|---|---|
| step timeout（每步） | orchestrator_v2 `_dispatch` | 无显式值时取 `system.task_timeout`（600），下限 300；code_execution 下限 600 | config `system.task_timeout`（热重载）；规划器规则 17 显式指定 600-900（长文） | 单步执行上限 |
| LLM 请求读超时 | llm_client `_send_request`（同步/流式） | 600 | env `LLM_REQUEST_TIMEOUT` | 单次 LLM 调用 |
| LLM 异步池超时 | llm_client `_get_async_client` | 600（与同步统一） | env `LLM_REQUEST_TIMEOUT` | 单次异步 LLM 调用 |
| LLM 探测超时 | llm_client `_probe_endpoint_status` | 20 | env `LLM_PROBE_TIMEOUT` | 健康/余额探测（必须短，防预检挂死） |
| code_execution worker 循环预算 | code_execution_worker 生成-修复循环 | 编排器下发 `step_deadline`，每轮前检查剩余时间 | step timeout 派生 | worker 内部循环总时长 |
| 任务过期（stale） | web_ui `_cleanup_stale_tasks` | 3600，且**豁免运行中任务** | config `system.stale_task_timeout` / env `STALE_TASK_TIMEOUT`（每轮循环读取） | 任务级总时限 |
| 计划确认 | orchestrator `_plan_confirm_timeout` | 300 | config `system.plan_confirm_timeout`（热重载） | 计划 HITL 等待 |
| 报告/修订确认 | orchestrator 两处确认 | min(plan_confirm_timeout, 600) | 同上 | 终稿 HITL 等待 |
| critic 评审窗口 | orchestrator `_critic_timeout` | 120 | config `system.critic_timeout`（热重载） | 计划评审等待（经 `_brpop_with_deadline` 分片轮询） |
| stall 看门狗 | orchestrator `_stall_timeout` | 60（唯一默认来源=热重载表） | config `system.stall_timeout`（热重载） | 依赖死锁检测（只在 in_flight==0 时触发，不杀运行步骤） |
| guardian 心跳判定 | worker_guardian `HEARTBEAT_TIMEOUT` | 45（=心跳间隔 10s × 4.5） | 代码常量 | worker 死亡判定；busy/active 状态受保护不复活 |
| 调度任务 | scheduled_jobs / scheduler | poll 20s；提交重试 30min×2；终态重提 1/日 | 代码常量 | 定时任务生命周期 |
| SSE 连接 | web_ui `_get_task_events` | 1800s 单连接上限 | 代码常量 | 前端实时通道（与 stale 无关联，勿再误解） |

## 二、强制不等式链

1. **step_timeout ≤ LLM_request_timeout**：单步上限必须小于单次 LLM 调用超时，否则步骤先超时、LLM 调用继续空烧（2026-09-07 的 60s 读超时 vs 300s 步超时 bug 即违反此条）。
2. **worker_loop_bound ≤ step_timeout**：worker 内部循环（如 code_execution 3×2 轮 LLM+子进程）必须在步骤超时前主动收口（`step_deadline` 下发实现）。
3. **stale_after ≥ 最坏合法总时长**：8 步×step_timeout + 反思重做（3 轮×300s）+ 修复轮（2×900s）+ 确认等待 ≤ stale_after；且 stale 判定必须**豁免运行中任务**（Redis `task_running:{tid}` / 内存 RUNNING 态）。
4. **探测超时 ≪ 业务超时**：健康/余额探测用 20s 级别，不得继承 600s 业务超时。

## 三、常见回归陷阱（改常量前必查）

- normalize_steps / 模板固化不得给步骤填死 timeout 默认（会架空 config `task_timeout`）。
- 新增"每步默认值"时先查 `_dispatch` 的 fallback 链与热重载表是否一致。
- task_history 全程 PENDING 直到终态——任何按 PENDING 时长的清理必须先豁免运行中任务。
- 异步/流式/同步三条 LLM 路径的超时必须保持同一口径（`LLM_REQUEST_TIMEOUT`）。
- 修改 guardian 心跳/复活条件时须保持"忙状态受保护"，防同 agent_id 双进程抢队列。
