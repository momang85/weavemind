## 网络访问决策：按可信来源和用途授权

允许个人版明确配置本地 Ollama/LoRA，允许银行管理员批准特定内部模型或业务服务。资料正文、任务指令、模型输出、搜索结果派生的 URL 只能走受约束的内容抓取通道。

建议收敛为共享网络策略模块和两类调用接口：

- `request_service(endpoint_id, operation, ...)`：后端解析注册端点；绑定用途、scheme、标准化 host、port、允许的操作/路径、租户和策略版本。个人单用户安装由本机操作者配置；银行版由授权管理员配置并审计。客户端不能提交 `trusted=true` 或 `allow_private=true` 自行提升权限。
- `fetch_document(url, ...)`：仅 http/https 公网内容；拒绝环回、私网、链路本地、共享/保留/非全局可路由地址及元数据服务。正常化 IPv4/IPv6 和映射地址，拒绝 URL 用户凭据与含糊解析。解析失败必须拒绝，所有解析结果均须满足策略。

具体要求：

1. 私网例外绑定到批准的具体服务，禁止全局 `allow_private=True`。例如模型调用可以访问登记的 `http://127.0.0.1:11434`，同一地址出现在网页或研究指令中仍拒绝。MCP、embedding、webhook 各自登记用途与权限，不能因“在配置文件里”就把普通用户可编辑的任意地址视为可信。
2. 默认关闭自动重定向；确需支持时每一跳重新校验地址和策略，限制次数，不向另一 origin 转发凭据。受信端点也不能重定向到任意内网地址。
3. 校验与连接须使用一致的目标解析结果，避免检查后由 HTTP 库再次解析到其他地址；使用固定已验 IP 且保留正确 Host/SNI/TLS 校验，或使用受控出口代理。银行部署另配网络出口限制，应用函数本身不能证明生产隔离。
4. 本机模型的明确 HTTP 例外只作用于登记的环回服务；其他服务维持 TLS 校验，不能用 `verify=False` 解决兼容问题。限制请求时长、响应体大小、并发与重试，审计仅记脱敏目标和策略判定。
5. **现有 `_validate_public_url` 不足以直接验收。** 本轮复现 DNS 解析失败仍返回 True，`100.64.0.1` 也被放行；代码自述仍有 DNS 二次解析竞态。复用前应修正并验证真实传输层，不能凭调用过该函数就将扫描结果判为误报。

网络验收最小集合：登记本地模型允许；相同 URL 经内容抓取拒绝；未登记私网服务拒绝；公网正常允许；DNS 失败、混合公网/私网解析、地址转换和重定向进入内网均拒绝；跨 origin 不携带模型凭据；重绑定不能改变最终连接目标。可用替身做控制流检查，真实出口隔离另记待验证。

设计依据：OWASP 区分已识别可信服务与任意外部地址的防护策略，并建议同时使用应用与网络控制、关闭自动跳转以防校验绕过。以上接口和部署边界是结合织光的架构选择。参考：[OWASP SSRF Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)。
