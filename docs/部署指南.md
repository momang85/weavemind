## 1. 部署方式总览

| 方式 | 前置条件 | 适用场景 | 默认访问地址 |
| --- | --- | --- | --- |
| **方式 C：Docker Compose**（推荐） | Docker Desktop / Docker Engine + compose | 无需本地 Python/Node，数据卷持久化，最适合服务器与生产化部署 | http://localhost:8080 |
| **方式 A：Windows 一键** | Windows + Python 3.10–3.14 + Docker Desktop（Node.js 18+ 可选） | Windows 本机最快上手 | http://localhost:8080（已构建前端）/ http://localhost:5173（回退页） |
| **方式 B：Linux / macOS 一键** | Python 3.10–3.14 + Docker（提供 Redis）（Node.js 18+ 可选） | Linux/macOS 本机快速部署 | 同上 |
| **方式 D：手动安装** | Python 3.10–3.14 + Redis（Docker 或本机）+ Node.js 18+（可选） | 自定义环境、二次开发、无 Docker 的内网机器 | 同上 |

通用前置：`git`、可访问所选 LLM 端点（使用私有化模型时保证同网段可达）。

## 2. 方式 C：Docker Compose（推荐）

### 2.1 前置条件

- Docker Desktop（Windows/macOS）或 Docker Engine + docker compose 插件（Linux）
- 无需本地安装 Python / Node.js（镜像内已包含）

### 2.2 配置 .env

```bash
cp .env.example .env        # Windows: copy .env.example .env
```

`.env` 与 `docker-compose.yml` 同目录，启动时注入到容器环境变量，不写入镜像。变量说明：

| 变量 | 是否必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `LLM_API_KEY` | **必填** | 无 | 执行模型密钥。未设置时 `docker compose up` 会直接报错中止 |
| `LLM_BASE_URL` | 可选 | `https://api.siliconflow.cn/v1` | 执行模型 OpenAI 兼容端点 |
| `LLM_MODEL` | 可选 | `deepseek-ai/DeepSeek-V3` | 执行模型名 |
| `EMBEDDING_API_KEY` | 可选 | 继承 `LLM_API_KEY` | 记忆向量化密钥，可单独覆盖 |
| `EMBEDDING_BASE_URL` | 可选 | 继承 `LLM_BASE_URL` | 向量化端点 |
| `EMBEDDING_MODEL` | 可选 | `BAAI/bge-large-zh-v1.5` | 向量模型 |

> 注意：`.env.example` 只列了最简必填项；需要覆盖 `EMBEDDING_*` 时直接在 `.env` 中追加即可（`docker-compose.yml` 已定义默认值）。方式 C 中 compose 已把 `REDIS_HOST=redis`、`REDIS_PORT=6379` 固定指向容器内 Redis，`.env.example` 里的 `REDIS_HOST/REDIS_PORT` 只在手动部署方式中生效。

### 2.3 启动与停止

```bash
docker compose up --build -d     # 首次构建并后台启动
docker compose logs -f app       # 跟踪应用日志
docker compose restart app       # 重启应用容器
docker compose down              # 停止（保留数据卷）
```

- 首次执行需拉取基础镜像并安装 npm/pip 依赖，通常需要数分钟
- 启动完成后访问 **http://localhost:8080**
- `docker compose down -v` 会连数据卷一起删除，**慎用**

### 2.4 数据持久化

| Docker 卷 | 挂载点 | 保存内容 |
| --- | --- | --- |
| `zhiguan_redis_data` | Redis `/data` | 队列、注册表、任务瞬时状态 |
| `zhiguan_app_data` | 容器 `/data` | `agents.db`、`chroma_memory/`、`metrics.csv`、`metrics_summary.json` |

- 停止或重建容器不会丢数据；只有显式 `docker compose down -v` 才会清除
- 任务工作区默认位于容器临时目录；如需持久化任务产物，请设置 `WEAVEMIND_WORKSPACE_ROOT` 指向挂载卷路径并额外挂载

## 3. 方式 A：Windows 一键

### 3.1 前置条件

- Windows 10/11
- Python 3.10–3.14（`python --version` 可用）
- Docker Desktop（脚本会自动启动；未安装会提示先安装）
- Node.js 18+（可选，仅首次自动构建前端时需要；没有 Node 也能以回退页启动）

### 3.2 步骤

```bat
git clone https://github.com/momang85/weavemind.git
cd weavemind
copy config.example.json config.json
:: 编辑 config.json，填写 llm.api_key / llm.base_url / llm.model
start.bat
```

`start.bat` 的自动化流程：

1. **校验配置**：读取 `config.json`，确认 `llm` 段含 `api_key`、`base_url`、`model`，缺失则提示并退出
2. **Redis**：检测 Docker 引擎；未运行则自动启动 Docker Desktop 并等待最多 90 秒；`zhiguan-redis` 容器存在则 `docker start`，不存在则 `docker run` 创建
3. **依赖**：自动 `pip install -r requirements.txt`（首次运行）
4. **前端**：`frontend/dist` 已存在则跳过；否则有 Node.js 时执行 `npm install && npm run build`；无 Node.js 时提示使用内置回退页
5. **启动**：`python launcher.py` 启动全部服务（PID 管理）
6. **打开浏览器**：已构建前端访问 8080，否则访问 5173

停止：双击 `stop.bat`，会先按 PID 停止全部服务，再询问是否同时停止 Redis 容器。

> 提示：如果系统装有多个 Python 版本，请确认 `python` 指向 3.10–3.14；首次运行安装依赖与构建前端耗时较长，属正常现象。

## 4. 方式 B：Linux / macOS 一键

### 4.1 前置条件

- Linux / macOS，`bash`
- Python 3.10–3.14
- Docker（用于提供 Redis）
- Node.js 18+（可选，仅首次自动构建前端时需要）

### 4.2 步骤

```bash
git clone https://github.com/momang85/weavemind.git
cd weavemind
cp config.example.json config.json    # 填写 llm 段
bash start.sh
```

`start.sh` 的自动化流程：

1. **Redis**：`zhiguan-redis` 容器已在运行则跳过，否则删除旧容器并 `docker run -d --name zhiguan-redis -p 6379:6379 redis:7-alpine`
2. **依赖**：`pip install -r requirements.txt`
3. **前端**：`frontend/dist` 缺失且有 Node.js 时执行 `npm install && npm run build`；无 Node.js 时使用回退页
4. **启动**：`python launcher.py` 启动全部服务，自动打开浏览器

停止：`bash stop.sh`（或 `python launcher.py stop`），脚本会询问是否同时停止 Redis 容器。

> 注意：`start.sh` 每次会先 `docker rm -f zhiguan-redis` 再重建（未挂载持久化卷），Redis 中的瞬时状态会被清空；任务记录与记忆保存在 `agents.db` 和 `chroma_memory/`，不受影响。需要 Redis 数据持久化请使用方式 C。

## 5. 方式 D：手动安装

适合无 Docker、内网隔离或需要二次开发的场景。全流程如下：

```bash
# 1. 创建虚拟环境（Windows: .venv\Scripts\activate）
python -m venv .venv
source .venv/bin/activate

# 2. 安装依赖（可选：pip install -r requirements-games.txt 提供 pygame-ce）
pip install -r requirements.txt

# 3. 前端生产构建（不想构建也可 npm run dev 走开发模式）
cd frontend && npm install && npm run build && cd ..

# 4. 生成配置文件并填写密钥
cp config.example.json config.json    # Windows: copy config.example.json config.json
# 至少填写 llm.api_key / llm.base_url / llm.model

# 5. 准备 Redis（任选其一）
docker run -d --name zhiguan-redis -p 6379:6379 redis:7-alpine
# 或使用本机 Redis 服务（默认 localhost:6379，可在 config.json redis 段修改）

# 6. 启动
python launcher.py                    # 等价于 python launcher.py start
```

- 已构建前端 → 访问 **http://localhost:8080**
- 未构建前端 → launcher 自动启动 Vite 开发服务器，访问 **http://localhost:5173**（功能受限）
- 开发模式可另行 `cd frontend && npm run dev`，Vite 已配置 `/api` 代理到 8080

## 6. 配置说明

### 6.1 config.json 各段含义

真实配置统一放在 `config.json`（已 `.gitignore`，不入库），模板见 `config.example.json`：

| 段 | 作用 | 关键字段 |
| --- | --- | --- |
| `llm` | **执行模型**：所有 Worker 实际干活/生成内容时调用 | `api_key`、`base_url`、`model` |
| `planner` | **规划器**：生成/修正任务计划专用模型，缺省复用 `llm` | `api_key`、`base_url`、`model` |
| `backup` | **双源 failover**：主端点连续失败或判定不健康时自动切换的备用 LLM；留空则不启用 | `api_key`、`base_url`、`model` |
| `embedding` | 记忆向量化（ChromaDB 长期记忆的写入与检索） | `api_key`（缺省继承 `LLM_API_KEY`）、`base_url`、`model` |
| `redis` | Redis 连接（任务队列、注册表、瞬时状态） | `host`、`port` |
| `system` | 运行旋钮（见 6.2） | 见下表 |
| `mcp_servers`（可选） | 第三方 MCP 服务器声明 | `[{"name","command","args"}]`（stdio）或 `[{"name","url"}]`（HTTP） |

### 6.2 system 旋钮

| 旋钮 | 默认值 | 含义 |
| --- | --- | --- |
| `task_timeout` | 300 | 单步任务超时（秒），`code_execution` 会自动放宽到 600 |
| `max_retry` | 2 | 步骤失败后的重试次数 |
| `replan_depth` | 2 | 失败后的单步重规划深度 |
| `guardian_heartbeat` | 20 | Worker 守护进程心跳检查间隔（秒） |
| `critic` | true | 是否启用计划评审（Critic） |
| `critic_timeout` | 30 | 等待评审结果的超时（秒） |
| `max_steps` | 8 | 单个计划的最大步骤数 |
| `max_parallel` | 3 | 无依赖步骤的最大并行数 |
| `max_iterations` | 2 | 自主迭代（评审→追加步骤）最大轮数，0 表示关闭 |
| `stall_timeout` | 300 | 无进展判定为卡死的秒数 |
| `plan_confirm_timeout` | 300 | 勾选“先确认计划”后的等待秒数，超时取消 |
| `scheduler` | false | 是否启用每日 3:00 自动进化（也可用环境变量 `EVOLUTION_SCHEDULE=1`） |

### 6.3 模型分级建议

- **`llm`（执行模型）**：调用量最大，建议选性价比高、速度快的模型（如 `deepseek-ai/DeepSeek-V3` 级别）
- **`planner`（规划器）**：规划质量直接决定任务成败，复杂目标建议配置比执行模型更强的推理/长上下文模型
- **`backup`（备用）**：建议与主端点**不同厂商、不同密钥**，避免主链路故障时单点失效
- **`embedding`**：`BAAI/bge-large-zh-v1.5` 对中文检索效果好；任意 OpenAI 兼容 embedding 端点均可替换
- 同一把密钥可复用到多个段；方式 C（Docker）中 `planner`/`backup` 默认复用 `LLM_*` 环境变量，需要三段独立配置时请使用非 Docker 方式（`config.json`）

### 6.4 环境变量

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `LLM_API_KEY` | 无 | 执行模型密钥（Docker 方式必填） |
| `LLM_BASE_URL` / `LLM_MODEL` | SiliconFlow / DeepSeek-V3 | 执行模型端点与模型名 |
| `EMBEDDING_API_KEY` / `EMBEDDING_BASE_URL` / `EMBEDDING_MODEL` | 继承 LLM / `bge-large-zh-v1.5` | 向量化配置 |
| `LLM_REQUEST_TIMEOUT` | 同步 60 / 异步流式 180 | 单次 LLM 请求超时（秒）；生产建议调到 30–60，快速暴露端点故障 |
| `WEB_PORT` | 8080 | WebUI/生产前端端口 |
| `REDIS_HOST` / `REDIS_PORT` | localhost / 6379 | Redis 地址 |
| `REGISTRY_DB` / `MEMORY_DIR` / `METRICS_FILE` / `METRICS_SUMMARY` | 项目根目录默认值 | 数据库、记忆目录、指标文件位置（Docker 中指向 `/data`） |
| `WEAVEMIND_WORKSPACE_ROOT` | `<temp>/agent_workspace/tasks` | 任务工作区根目录 |
| `CODE_EXECUTION_SANDBOX` | 自动（docker-first） | 代码执行沙箱模式：`docker` / `restricted` / `none`；未设置时自动探测，docker 可用则 docker，否则 restricted |
| `CODE_SANDBOX_IMAGE` / `CODE_SANDBOX_MEM` / `CODE_SANDBOX_CPUS` | `weavemind-code-sandbox:latest` / 512m / 1 | docker 沙箱镜像与资源限制 |
| `EVOLUTION_SCHEDULE` | 0 | 置 1 开启每日自动进化 |
| `RATE_LIMIT_PER_MIN` | 30 | 每 IP 每分钟 API 限流次数 |
| `STALE_TASK_TIMEOUT` | 1800 | 任务被判定为陈旧（不再展示为活跃）的秒数 |

### 6.5 配置生效方式

- **热重载**：`llm` / `planner` / `backup` / `embedding` 段修改 `config.json` 后进程内自动生效（mtime 检测），无需重启
- **需重启**：`system` 段旋钮、`CODE_EXECUTION_SANDBOX` 等环境变量，修改后执行 `python launcher.py restart`
- Docker 方式以 `.env` 为准（容器内没有 `config.json`）

## 7. 运维

### 7.1 launcher.py 进程管理

| 命令 | 说明 |
| --- | --- |
| `python launcher.py`（或 `python launcher.py start`） | 启动全部服务（先按 PID 精确停止旧进程） |
| `python launcher.py stop` | 按 `.weavemind/pids.json` 精确停止全部服务 |
| `python launcher.py restart` | 先停后起（间隔 2 秒） |
| `python launcher.py status` | 查看每个服务的 UP/DOWN 状态与 PID |

启动的服务包括：全部 Worker（`search` / `web-fetch` / `content-summary` / `code-execution` / `file-io` / `packaging` / `data-loader` / `data-analyzer` / `model-trainer` / `report-generator` / `react-agent`）、`critic`、`orchestrator`、`webui`、`guardian`、`metrics`，以及可选的 `scheduler`（每日进化）和 `vite`（开发模式前端）。

### 7.2 Redis 故障排查

任务一直卡在 **PENDING** 时，按顺序排查：

1. 看容器是否在跑：`docker ps --filter name=zhiguan-redis`
2. 测连通性：`docker exec zhiguan-redis redis-cli ping`，返回 `PONG` 即正常
3. 容器存在但已停止：`docker start zhiguan-redis`
4. 容器不存在：`docker run -d --name zhiguan-redis -p 6379:6379 redis:7-alpine`
5. 检查进程：`python launcher.py status`，必要时 `python launcher.py restart`
6. Windows 下确认 Docker Desktop 已就绪（`start.bat` 会自动拉起并等待最多 90 秒）
7. 若 6379 被其他程序占用，改用其他端口并同步 `config.json redis` 段 / `REDIS_PORT`

### 7.3 日志

- **位置**：项目根目录 `logs/`（已 `.gitignore`，不入库）
- **轮转**：单文件 5MB，保留 3 份备份（`*.log.1` / `.2` / `.3`），自动轮转
- **常用日志**：`launcher.log`、`orchestrator.log`、`critic.log`、`webui.log`、`worker-*.log`；开发模式另有 `vite.log`；MCP/工具调用审计在 `logs/tool_audit.jsonl`
- 排查 LLM 401/402 时优先在对应日志中搜索 `HTTP 401` / `HTTP 402` 与响应体

### 7.4 数据目录

| 数据 | 默认位置（手动部署） | Docker 位置 | 说明 |
| --- | --- | --- | --- |
| `agents.db` | 项目根目录 | `/data`（`app_data` 卷） | SQLite 注册表：任务/会话/历史 |
| `chroma_memory/` | 项目根目录 | `/data`（`app_data` 卷） | ChromaDB 长期记忆与策略沉淀 |
| `metrics.csv` | 项目根目录 | `/data`（`app_data` 卷） | LLM 用量与指标 |
| `metrics_summary.json` / `evolution_history.json` | 项目根目录 | `/data`（`app_data` 卷） | 指标汇总 / 进化记录 |
| tasks 任务工作区 | `<系统临时目录>/agent_workspace/tasks` | 容器临时目录 | 每个任务一个目录（`project/`、`reports/`、`data/`、`charts/` + 最终 zip） |

任务工作区默认在系统临时目录，重启可能被系统清理；如需长期保留，用环境变量指定：

```bash
export WEAVEMIND_WORKSPACE_ROOT=/data/tasks    # Linux/macOS
set WEAVEMIND_WORKSPACE_ROOT=D:\data\tasks     # Windows CMD
```

**备份建议**：停服后复制 `agents.db`、`chroma_memory/`、`metrics.csv` 与任务工作区即可完整备份。Docker 方式先 `docker compose stop`，再用 `docker cp zhiguan-app:/data/. ./backup-data` 备份应用数据；Redis 卷（队列/瞬时状态）按需备份。

## 8. 安全

### 8.1 密钥管理

- `config.json` 与 `.env` 均已加入 `.gitignore`，密钥不会入库
- 密钥只写在本地文件，提交前执行 `git status` 确认；可用 `python scripts/check_secrets.py` 扫描误提交的密钥
- Docker 镜像构建过程不写入密钥，仅在运行时通过 `.env` 注入环境变量

### 8.2 代码执行沙箱（O-01）：docker-first 自动降级

`code_execution` 沙箱提供三种模式，默认策略为「docker-first 自动降级」：

| 模式 | 说明 |
| --- | --- |
| `restricted` | 密钥剥离 + 工作区限定 + 超时；子进程仍在宿主机运行 |
| `docker` | 容器级隔离：`--network none` 断网、`--read-only` 只读根文件系统、`--tmpfs /tmp`、内存/CPU 限制、仅挂载任务工作区 |
| `none` | 不隔离，仅供完全可信的本地调试，**生产环境不要使用** |

**默认行为（无需任何配置）**：

1. 未设置 `CODE_EXECUTION_SANDBOX` 时自动探测：docker CLI 与守护进程可用（`docker version` 能返回 Server 段）且沙箱镜像存在 → 使用 `docker`；否则使用 `restricted`。
2. 显式设置 `CODE_EXECUTION_SANDBOX=docker` 时按显式值执行；若 docker 执行层失败（守护进程未启动、镜像缺失、权限不足等），该次执行自动降级 `restricted` 重跑，结果带降级标记并在日志说明原因，**不吞掉脚本自身报错**（脚本 Traceback 不会被当作 docker 不可用）。
3. docker 模式下每次执行前检查镜像是否存在（`docker image inspect`）；缺失时打印构建提示，**不自动拉取/构建**（避免长时间阻塞任务），该次执行降级 `restricted`。

首次使用 docker 模式前需构建沙箱镜像：

```bash
docker build -f Dockerfile.sandbox -t weavemind-code-sandbox:latest .
```

需要**显式强制**某一种模式时：

```bash
# 方式 A/B/D：启动前设置环境变量
export CODE_EXECUTION_SANDBOX=docker    # Linux/macOS
set CODE_EXECUTION_SANDBOX=docker       # Windows CMD

# 方式 C：在 docker-compose.yml 的 app 段 environment 中追加
#   - CODE_EXECUTION_SANDBOX=docker
```

可用 `CODE_SANDBOX_MEM`（默认 `512m`）、`CODE_SANDBOX_CPUS`（默认 `1`）调整资源上限；`CODE_SANDBOX_IMAGE`（默认 `weavemind-code-sandbox:latest`）指定镜像名。

**确认沙箱生效**：`/api/status`（需登录）或公开的 `/api/health` 返回 `code_sandbox` 字段：

```json
{
  "mode": "docker",
  "mode_explicit": null,
  "mode_env_raw": null,
  "mode_source": "auto",
  "docker_available": true,
  "sandbox_image": "weavemind-code-sandbox:latest",
  "sandbox_image_exists": true
}
```

- `mode`：实际生效模式；`mode_source` 为 `explicit`（显式设置）或 `auto`（自动探测）
- `docker_available`：docker 守护进程是否可响应
- `sandbox_image_exists`：沙箱镜像是否已构建（缺失时本次执行会自动降级 restricted）

### 8.3 code_execution 恶意样例防护

- **密钥剥离**：子进程环境会过滤所有含 `LLM_`、`OPENAI_`、`EMBEDDING_`、`API_KEY`、`SERPAPI`、`TOKEN`、`SECRET` 前缀的变量，生成的代码读不到任何密钥
- **范围限定**：仅挂载/允许访问任务工作区，配合超时强制终止
- **docker 模式**：断网 + 只读根文件系统 + 内存/CPU 限额，最大限度降低提权与横向移动风险
- **规划器约束**：财报/研报/调研类任务禁止 `code_execution` 抓网页或解析在线数据，只能做本地数据处理/计算

## 9. 常见问题 FAQ

### 9.1 端口占用

- **8080 被占用**：修改 `WEB_PORT` 环境变量（Docker 方式同时改 `docker-compose.yml` 的端口映射），或结束占用进程
- **5173 被占用**：修改 `frontend/vite.config.ts` 中 `server.port`
- **6379 被占用**：换端口后同步修改 `config.json redis` 段或 `REDIS_PORT`；`start.bat`/`start.sh` 固定映射 6379，需先释放
- 查询占用：Windows `netstat -ano | findstr 8080`；Linux/macOS `lsof -i :8080`

### 9.2 前端未构建/回退页

- **现象**：8080 打开只有简单回退页或空白；5173 报找不到模块
- **原因**：`frontend/dist` 不存在，且本机没有 Node.js 或前端构建失败
- **解决**：安装 Node.js 18+ 后执行 `cd frontend && npm install && npm run build`，再 `python launcher.py restart`；不想构建可继续使用 5173 开发模式（功能受限）

### 9.3 LLM 端点 401/402 排查

`llm`（执行）、`planner`（规划）、`backup`（备用）三段各自持有 `api_key`，逐段检查：

- **401**：对应段的 `api_key` 错误或无权限。检查是否仍是示例值 `YOUR_API_KEY`、有无多余空格/换行；Docker 方式检查 `.env` 的 `LLM_API_KEY`
- **402**：账户余额不足或套餐失效，登录对应 key 所属平台查看
- `base_url` 必须是 OpenAI 兼容格式（能拼出 `/chat/completions`，例如 `https://api.siliconflow.cn/v1`）
- 修改 `config.json` 后 LLM 配置热重载，无需重启；日志（`logs/orchestrator.log`、`logs/worker-*.log`）会记录 `HTTP 401/402` 与响应体
- 可用 curl 直接验证密钥与端点：

```bash
curl https://api.siliconflow.cn/v1/chat/completions \
  -H "Authorization: Bearer $LLM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"deepseek-ai/DeepSeek-V3","messages":[{"role":"user","content":"ping"}]}'
```

### 9.4 Python 版本 3.10–3.14 与 pygame-ce

- 织光支持 Python 3.10–3.14
- 官方 `pygame` 在 3.14 暂无 wheel；请使用 **pygame-ce 2.5.6+**（社区版，drop-in 替代，导入名仍是 `pygame`）
- 执行 `pip install -r requirements-games.txt` 安装可选依赖；系统自动探测：有 pygame 用 pygame，没有则引导生成 turtle / 单文件 HTML 方案，不影响其他功能

### 9.5 Docker Desktop 未启动

- **方式 A**：`start.bat` 会自动启动 Docker Desktop 并等待最多 90 秒；仍失败请手动打开 Docker Desktop 后重跑
- **方式 B / C**：先手动启动 Docker Desktop（或 docker daemon），`docker info` 输出正常后再执行
- **方式 D**：不需要 Docker，使用本机 Redis 即可
- 验证容器：`docker ps --filter name=zhiguan-redis`
