## 2. 开放门槛（必须全部满足，缺一不开放）

1. **期数**：同一主体、同一合并口径、**≥5 个连续年度**的年度观察（含期初），且期间无口径变更；
   有会计政策/追溯重述时，需能定位"当时可见版本"（更正稿不得当作历史时点已知，见 §3.2）。
2. **样本量与同质性**：单公司时序预测需 ≥8 个年度观察；跨公司面板需 ≥30 个公司-年度，
   且行业/规模分层写明，不允许把不同商业模式混池。
3. **输出可被独立复算**：预测必须给出所用样本、方法版本、参数、随机种子（若有）与**样本外**
   评估（滚动回测，至少 3 折），并能由第三方仅用包内字节复算出同一数值。
4. **不确定性的表述**：只允许"区间 + 方法 + 假设"的形式，禁止单点数值冒充结论；区间必须写明
   覆盖率依据（如回测覆盖率），不得用主观百分比。
5. **与现状的可分性**：预测输出必须**单独分区**（不混进 `## 分析` 的确定性结论），
   正文、底稿、包内清单都要能一眼区分"历史事实 / 用户设定情景 / 统计预测"。
6. **验收与状态**：新增独立验证项（数据充分性、样本外一致性、口径一致、区间覆盖率）；
   机器验收只证明技术交付，**真人复核**仍需人工完成，二者不得互相替代。
7. **批准人**：由架构师/项目负责人在书面指令里显式开启（本文件不能自行开启），并同时给出
   允许的模型族、最大回溯窗口与失效条件。

## 3. 禁用清单（即使开放后也不得做）

1. **禁止目标价、买卖建议、授信结论、收益承诺**——产品定位明确不做自动交易/授信/目标价。
2. **禁止把更正稿、后续披露当"当时已知"**：历史时点研究只能用截至研究时点已披露的版本；
   更正稿与原文并存，不得覆盖、不得回溯替换。
3. **禁止跨主体/跨币种/跨口径混算**：预测样本必须与研究对象同主体、同币种、同口径
   （与 `contracts.full_identity_ok` 同一纪律）。
4. **禁止用推算/插值填补缺失期**：缺失就是缺失，宁可拒绝出预测并说明缺口。
5. **禁止把"用户设定情景"称作预测**：情景是用户给定参数的确定性推演（本版本已有），
   不得赋予概率或置信度，也不得与统计预测混排。
6. **禁止在期数不足时降级交付**：样本不足必须**拒绝**并给出门槛差距，不得"先给个数再声明不准"。
7. **禁止概率化措辞替代方法**：不得出现"大概率/基本可以确定/预计增长 X%"这类无方法支撑的表述。

## 4. 当前行为（已在产品里落地，不是一句口号）

预测类问题（含"预测/预计/展望/概率/外推/回归/目标价/估值/明年/未来/趋势…"）现在命中
**显式的问题类型** `forecast_trend`（`financial_analysis/questions.py`），该类型 `models=()`：

- 编译计划**不采用任何注册模型**（此前会退回"按输入齐备性选模型"，把利润桥/现金质量/营运资金
  当成对"预测明年收入"的回答——这是被修掉的误导）；
- 计划说明里写明"预测/趋势外推本版本不开放：不采用任何注册模型、不出预测数"并指向本文件；
- 其余注册模型逐条带理由进 `rejected`（"与所问问题无关"，并写明它回答的是哪一类问题）；
- **否定语境不算命中**："不做情景预测，只看现金转化"仍然只选现金类模型。
